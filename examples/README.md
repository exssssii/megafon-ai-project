# Учебные кейсы

Два предварительных кейса для проверки агента на разных задачах и третий, к которому бриф выдаётся отдельно. Это не официальный бриф хакатона: когда он появится, демонстрационный кейс будет с ним сверен.

Продукты и компании вымышлены, совпадения случайны. Числа в файлах — собственные учебные данные. Сайты, указанные в запросах, настоящие и публичные.

| Папка | Вопрос руководителя |
|---|---|
| [`retention-smb`](retention-smb/request.md) | Почему просело удержание сервиса онлайн-записи |
| [`direction-b2c`](direction-b2c/request.md) | Куда развивать приложение для владельцев питомцев |
| [`family-connect`](family-connect/request.md) | Что сдать по брифу «Связь для близких и собственных устройств» («Пример брифа») |

В `request.md` лежит запрос, с которого начинается работа. Основные материалы находятся в `materials/`. Папка `extra/` выдаётся только по сценарию приёмки, в обычном прогоне её не используют.

Кейс `family-connect` состоит из одного `request.md`, написанного вручную. Пример содержит только запрос. Бриф лежит в демопроекте, [`demo/family-connect/sources/brief.pdf`](../demo/family-connect/sources/brief.pdf), а в живой прогон он попадает копией вне папки репозитория через параметр `-Brief` скрипта `scripts/live-entry.ps1` ([ожидания](../docs/acceptance/family-connect.md)).

Файлы двух первых кейсов создаёт `tools/make_acceptance_cases.py`, вручную они не правятся. Запуск:

```text
uv run --group fixtures python tools/make_acceptance_cases.py
```

Повторный запуск даёт те же байты: время записи в xlsx и docx зафиксировано. PDF встраивает шрифт, поэтому на машине с другим файлом шрифта его байты могут отличаться при том же тексте.
