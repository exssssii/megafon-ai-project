# Маршрут модельного собеседника

Процедура общая для любой среды и подключается из шага 6 [`interviews.md`](interviews.md#шаги): если этот файл есть, беседы шага 6 идут по нему, если нет, как раньше. Правила собеседника — [`respondent.md`](../roles/respondent.md), журнал действий — [`checkpoint.md`](checkpoint.md#журнал-действий). Команды запускаются из корня папки, на Windows через `.venv/Scripts/python.exe`, в других системах через `.venv/bin/python`.

Смысл маршрута: собеседник отвечает двумя–четырьмя предложениями по карточке и ничего не подтверждает, поэтому первую попытку делает дешёвая модель, а при провале проверки роли та же беседа повторяется на модели сессии. Выигрыш в расходе не обещается: он считается по журналу прогона.

## Какая модель

| Среда | Первая попытка | Повтор |
|---|---|---|
| Claude Code | субагент `respondent`, параметр `model: haiku` у инструмента вызова субагента; среда называет эту модель `claude-haiku-5-5` | тот же вызов без параметра `model` |
| Codex | `spawn_agent` с `fork_turns: "none"` и параметром `model: gpt-6-luna` | тот же вызов без параметра `model` |
| Другая среда с субагентами | параметр модели, если инструмент его принимает | без параметра |
| Среда без субагентов, запасной путь `chat_persona` | маршрута нет: отвечает модель сессии | — |

В Codex при включённом маршруте беседа идёт через `spawn_agent`, даже если среда показывает субагента `respondent`: у него нет параметра модели. Текст `respondent.md` и задание передаются в `message`, `task_name` вида `respondent_1`, как в шаге 6.

Дешёвую модель пиши в шапке только если действительно передал параметр. Модель сессии назови так, как её называет среда, по правилу из [`checkpoint.md`](checkpoint.md#журнал-действий); если среда её не называет, ключ `--model` у повтора не передавай, а в шапке напиши `модель сессии`.

## Ход одной беседы

Для каждого персонажа отдельно. Повтор по проверке роли не новая беседа: файл и номер те же, предел в три беседы и решение `budget` он не задевает. Повтор после правки карточки пользователем идёт как раньше, новым файлом, и тоже начинается с дешёвой модели.

1. Запиши начало действия и вызови субагента с параметром модели (в Claude Code `model: haiku`, в Codex `model: gpt-6-luna`). Ключ `--input-ref` и остальное — как в шаге 6.

```text
tools/checkpoint.py action start projects/<case-id> --kind model --tool respondent --environment <среда> --model <дешёвая модель> [--input-ref …]
```

2. Запиши беседу в `sources/interviews/synthetic-<персонаж>-<n>.md` в формате шага 7, ответы дословно. В шапку добавь строку `Модель: <дешёвая модель> (маршрут)`. Файл пока не регистрируй как источник. Запусти проверку:

```text
tools/role_check.py check projects/<case-id> sources/interviews/synthetic-<персонаж>-<n>.md
```

3. Код 0, роль пройдена: допиши в шапку строку `Проверка роли: пройдена`, закрой действие `action end --id ACT-… --outcome completed` и зарегистрируй источник, как в шаге 7.
4. Код 1, роль не пройдена. Допиши в шапку `Проверка роли: не пройдена (<коды через запятую>)`, перенеси файл в `state/interviews/rejected-<персонаж>-<n>.md` (папку создай; файл остаётся без регистрации и в источники не попадает), закрой действие `action end --id ACT-… --outcome failed`. Затем повтори на модели сессии: тот же `kind`, `tool`, `input_ref`, вызов без параметра модели, с текстом `respondent.md` в задании.

```text
tools/checkpoint.py action start projects/<case-id> --kind model --tool respondent --environment <среда> --model <модель сессии> --retry-of ACT-… --retry-reason 'role_check: <коды>' [--input-ref …]
```

   Ответ запиши снова в `sources/interviews/synthetic-<персонаж>-<n>.md` со строкой `Модель: <модель сессии> (повтор)`, снова запусти проверку и допиши `Проверка роли`. Прошла: как в пункте 3, источник регистрируется. Не прошла: пункт 5.
5. Повтор тоже не прошёл: третьей попытки нет. Допиши `Проверка роли: не пройдена (<коды>)`, зарегистрируй беседу, как в шаге 7, закрой действие `completed`. В итоге бесед скажи пользователю одной фразой, что в такой беседе форма ответа не прошла проверку. Гипотезы из неё записываются по общим правилам: синтетика ничего не подтверждает.
6. Код 4 или 5: проверка не выполнена (нет карточки, шапка не разбирается, сбой утилиты). Один раз исправь шапку по названной в ответе утилиты причине (при коде 5 причина в шапке: `сбой утилиты`) и запусти проверку снова. Если отказ остался, допиши `Проверка роли: не проведена (<причина>)`, зарегистрируй беседу, закрой действие `completed` и скажи пользователю одной фразой, что проверка роли не выполнялась.

Любую строку шапки можно исправить (в том числе `Персонаж: …, карточка …`). Ответы собеседника после записи не правятся: запрет шага 7 действует и здесь.

После перерыва: если в `sources/interviews/` лежит файл беседы, не зарегистрированный как источник и без строки `Проверка роли`, сначала запусти проверку роли и продолжай по пунктам 3–6; непроверенную беседу не регистрируй.

### Ответ «Роль не загружена»

Это сбой загрузки, а не провал проверки. Закрой действие `failed`, повтори вызов на той же дешёвой модели с параметром, с текстом `respondent.md` в задании, с `--retry-of` и причиной `роль не загружена`. Проверка роли применяется к ответу этого повтора, дальше пункты 3–5. Если ответ «Роль не загружена» всё же попал в файл, проверка вернёт `ROLE_NOT_LOADED`: такой ответ пройденным не бывает.

### Строки шапки

К строкам шага 7 добавляются две:

```text
Модель: <дешёвая модель> (маршрут) | <модель сессии> (повтор) | <модель сессии>
Проверка роли: пройдена | не пройдена (TOO_LONG, FOREIGN_NUMBER) | не проведена (<причина>)
```

Выбери один вариант: `(маршрут)` у первой попытки на дешёвой модели, `(повтор)` у повтора по проверке роли, без пометки у беседы вне маршрута (`chat_persona`, среда без параметра модели). Без этого файла строк нет.

## Что проверка роли видит и чего нет

Утилита проверяет форму: длину, число из ничего, речь за других, выход из роли и «Роль не загружена». Подыгрывание вопросу, выдуманные обстоятельства без чисел и ответ не по карточке она не видит. Её «пройдена» не значит, что ответ верен или полезен; синтетика по-прежнему ничего не подтверждает. На запасном пути `chat_persona` и в среде без параметра модели проверка тоже запускается; при провале повтора нет, действует пункт 5.

## Выключение

Нет этого файла — нет маршрута, процедура шага 6 идёт как раньше, строки `Модель` и `Проверка роли` не пишутся, валидатор их не требует.
