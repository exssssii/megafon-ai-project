# Журнал пересмотров `outputs/revisions.md`

Заголовок файла `# Пересмотры`, затем записи по порядку, новые в конце. Номер в заголовке идёт подряд с 1, в том числе для записей «изменений нет». Каждая запись:

```markdown
## Пересмотр 2 — 2026-11-20

- Новые данные: [SRC-0014]
- Изменилось: [CLM-0007] было «…», стало «…» [CLM-0031]
- Условия пересмотра: сработало «…» | не сработало ни одно
- Затронуто: product-strategy.md «Ценность»; commitments.md «Действия»; [CALC-0004]
- Не затронуто: communication-strategy.md; validation-plan.md
- Выбор: [DEC-0012] | изменений нет
- Прежние версии: outputs/.history/2/ | нет
```

Формат журнала проверяется всегда, когда файл есть, даже без решений `revision`. Все семь строк обязательны, каждая встречается один раз. Каждое решение `revision` в статусе `chosen` или `superseded` названо в строке `Выбор` ровно одной записи. У записи с решением есть папка `outputs/.history/<N>/` с файлами, а в `Прежние версии` стоит её путь; запись «изменений нет» снимка не требует и пишет `нет`. Если запись называет `validation-plan.md` или `commitments.md` в строке `Затронуто`, согласие с порогами или обязательствами должно быть дано не раньше последнего такого решения `revision`.

`tools/revision.py affected` разбирает только файлы `outputs/*.md` (не подпапки), без `revisions.md` и `accounting.md`: отчёт об учёте переписывает шаг учёта, а не пересмотр. Строка статуса сама по себе затронутым разделом не считается.
