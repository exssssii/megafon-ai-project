# Контракты данных кейса

Этот каталог описывает формат папки кейса `projects/<case-id>/`. По нему исполнитель, не читавший спецификацию, пишет запись любой сущности, а валидатор `tools/validate_project.py` проверяет форму и связи. Источник правил — [спецификация B01](../../docs/specs/2026-11-05-b01-contracts.md); при расхождении верна она.

Состав каталога:

- `versions.json` — поддерживаемые версии формата и миграции;
- `schemas/*.schema.json` — JSON Schema (Draft 2020-12), по одной на тип файла, общие определения в `common.schema.json`;
- `examples/valid/demo-case/` — связный кейс с вымышленными учебными данными, образец для всех типов записей;
- `examples/invalid/<случай>/` — по одному нарушению на папку, только для тестов;
- [`modes.md`](modes.md) — правила режимов продукта и разработки.

Пользовательские кейсы лежат в `projects/`, этот каталог в `.gitignore` и не публикуется. Кейс не должен зависеть от чата, `.work/`, личных путей и секретов.

## Папка кейса

| Путь от корня кейса | Содержимое | Запись |
|---|---|---|
| `case.json` | версия формата, `case_id`, название, дата создания | один раз; единственный обязательный файл |
| `brief.md` | бриф | текст, без контракта; утилиты читают разделы `Бюджет исследования` и `Слова пользователя` |
| `sources/` | копии материалов (беседы с модельными клиентами — `sources/interviews/synthetic-<персонаж>-<n>.md`, разделы `## Вопрос N`); извлечённый текст в `sources/extracted/<SRC-id>.jsonl`, отчёт чтения в `sources/extracted/<SRC-id>.report.json` | исходные файлы не меняются после регистрации; `sources/extracted/` обновляется повторным чтением, пока на источник нет ссылок; `sources/incoming/` — временные файлы страниц и запросов утилит, утилита удаляет их после выполнения |
| `evidence/sources.json` | источники (`SRC`) | реестр |
| `evidence/claims.json` | утверждения (`CLM`) | реестр |
| `evidence/calculations.json` | расчёты (`CALC`) | реестр |
| `research/questions.json` | вопросы исследования (`Q`) | реестр |
| `decisions/options.json` | варианты (`OPT`) | реестр |
| `decisions/decisions.json` | предложения и выбор (`DEC`) | реестр |
| `outputs/**/*.md` | стратегии и план проверки, подпапки допускаются | текст со ссылками вида `[CLM-0001]` |
| `outputs/interview-guide.md` | гайд бесед с модельными клиентами | текст со ссылками; пишется на этапе `research`, если выбран `interview_method` |
| `research/interviews/personas.md` | карточки персонажей для бесед | текст; изменение карточки — новая беседа |
| `outputs/commitments.md` | решение и обязательства: действия с ответственными и сроками, условия пересмотра, ссылка на согласие | текст со ссылками; пишется на этапе `validation_plan`, правится при пересмотре |
| `outputs/revisions.md` | журнал пересмотров после новых данных | только дописывание в конец; формат ниже |
| `outputs/.history/<N>/` | копии файлов `outputs/*.md` до пересмотра номер `N`, кроме `revisions.md` | пишет `tools/revision.py snapshot`; после записи не меняются; валидатор папку пропускает |
| `state/actions.jsonl` | журнал действий (`ACT`) | только дописывание |
| `state/checkpoints/CKP-NNNN.json` | checkpoint (`CKP`) | новый файл на каждое сохранение |
| `state/snapshots/<sha256>` | копии артефактов checkpoint, имя — отпечаток содержимого | файлы не меняются и не удаляются; пишет `tools/checkpoint.py` |

Реестр — JSON-объект `{"format_version": 1, "records": [...]}`. Нет файла реестра — реестр пуст. Записи не удаляются: отзыв выражается статусом и причиной.

## ID, даты, пути

- ID имеет вид `ПРЕФИКС-NNNN`, минимум четыре цифры: `SRC`, `CLM`, `CALC`, `Q`, `OPT`, `DEC`, `ACT`, `CKP`. Следующий номер — максимальный существующий плюс один, дополненный нулями.
- ID уникален в кейсе и не используется повторно, в том числе после отзыва. Префикс задаёт тип: ссылка на запись другого типа — ошибка `ID_WRONG_TYPE`.
- `case_id`: строчные латинские буквы, цифры и дефис; совпадает с именем папки кейса.
- Даты — RFC 3339 со смещением: `2026-11-05T14:30:00+03:00` или с `Z`. Несуществующая дата, дата без смещения или с пробелом вместо `T` — `SCHEMA`.
- Значения ID, `topic` и `case_id` проверяются целиком: перевод строки в конце, не-ASCII цифры и лишние символы — `SCHEMA`.
- Пути в записях — относительные от корня кейса, через `/`. Нельзя: начало с `/`, обратная косая черта, двоеточие (буква диска), сегменты `.` и `..`, выход за корень. Нарушение — `PATH_UNSAFE`. Путь файла источника начинается с `sources/`. `url` источника и `source_url` — только `http` или `https`, иначе `PATH_UNSAFE`; абсолютный путь в `reproduce` расчёта — тоже.
- Неизвестное значение записывается как `null`, а не нулём и не пустой строкой. Необязательные поля (`status_reason`, `source_url`, `supersedes`, `change_reason`, `choice`, `retry_of`, `retry_reason`, `runtime`, `delegated`, `resolution`, `quote`, `estimate_source`, `amounts`) при отсутствии значения не пишутся вовсе, `null` в них не допускается. `null` допустим только там, где он назван в описании типа (например, `proposal`, `limits`, `gap`, `model`, `previous`, `sha256` для `url`).

## Изображения и наблюдения

Расширение перечислений `type` и `locator.kind` не меняет версию формата: кейсы без изображений читаются без изменений.

- **Регистрация.** `tools/read_material.py add` принимает `.png`, `.jpg`, `.jpeg`, `.webp`. Формат проверяется по заголовку, а не по расширению; читаются формат, ширина и высота, пиксели и содержимое не читаются. Подделанное расширение, обрезанный файл (у PNG в последних 64 байтах нет блока `IEND`, у JPEG нет маркера конца `FF D9`) и анимация (WebP с флагом анимации, PNG с блоком `acTL`; причина «анимация не поддерживается») — код 2, источник не записывается. Сторона больше `max_image_side` — как у других форматов: источник записывается со статусом чтения `over_limit`, код 3, наблюдения для него не принимаются. После успешного `add` источник `partial`, `complete: false`, блоков нет, в `limits` «Изображение PNG 1366×768. Наблюдения не записаны.»; файл `sources/extracted/<SRC-id>.jsonl` пустой, `EXTRACT_MISSING` не выдаётся. Очень высокое изображение (высота больше ширины в 2,5 раза) получает в `limits` пометку, что детали могут потеряться.
- **Наблюдения.** Агент смотрит изображение и пишет файл `sources/incoming/<имя>.md`, `tools/read_material.py add-observations <case> <SRC-id> --text-file <файл>` разбирает его и пишет блоки `region`. Формат файла: `## Экран` (метка `целевой`, `заслонён`, `вход`, `капча`, `ошибка`, `пусто` или `другое` и одна строка), `## Наблюдение N` с N с единицы подряд (три строки `Где:`, `Видно:`, `Текст:`; строка `Текст:` — либо ровно `нет`, либо ровно `неразборчиво`, либо только цитаты в «…», разделённые запятыми, точками с запятой или пробелами; всё вне кавычек — ошибка формата), `## Не разобрано` (обязателен, допустим `нет`). Блок: `{"n": N, "locator": {"kind": "region", "index": N, "area": "<строка Где>"}, "text": "Где: …
Видно: …
Текст: …"}`. `quote` проверяется только по части блока после `Текст:`: место (`Где:`), описание (`Видно:`) и сами метки не цитируются.
- **Статусы.** Метка не `целевой`: `unavailable`, блоков нет (выход 2). Метка `целевой`: нужно хотя бы одно наблюдение, статус `ok`, если `## Не разобрано` — `нет` и снято всё, иначе `partial`. Повторная команда переписывает наблюдения, пока на источник нет ссылок; после ссылки — отказ (код 4), источник отзывают и регистрируют заново.
- **Снимки страниц.** `tools/read_material.py capture-web <case> --url <адрес> --title <название> [--mobile]` (необязательная группа `screenshots`) записывает части страницы как источники `image` с `origin: public_web`, `location.path` вида `sources/capture-<SRC-id>.png`, общими `source_url` (адрес после переадресации) и `retrieved_at` и названием «<название>, экран i из n». Все части попадают в реестр одной записью. Если снята не вся страница, у последней части в `sources/extracted/<SRC-id>.report.json` стоит `capture_incomplete` («Снято k из n экранов.»), статус остаётся `partial`, а `add-observations` сохраняет эту пометку в начале `limits` и не поднимает статус до `ok`. Адрес и каждый шаг цепочки переадресаций проверяются правилом публичных адресов, запросы страницы пропускаются только к публичным адресам, всплывающие окна закрываются, сокеты не соединяются. Правило применяется к имени, которое видит программа, а браузер разрешает его сам ещё раз, поэтому защита от подмены ответа DNS между двумя разрешениями не гарантируется (ограничение записано в [environments.md](../../docs/environments.md#изображения-e04)). Весь снимок ограничен `capture_timeout_seconds` плюс запас: по истечении браузер останавливается, ответ — `timeout`.
- **Признаки отказов.** `capture_unavailable` (нет Playwright или браузера, в ответе поле `install` с двумя командами), `budget_exhausted`, `action_missing` и `fetch_error`: `network_unavailable`, `address_blocked`, `http_error`, `timeout`, `blank_page`, `capture_unreadable`.
- **Утверждения.** `region` допустим только для `image` (иначе `LOCATOR_MISMATCH`), несуществующий номер наблюдения — `LOCATOR_NOT_FOUND`, цитата не из наблюдения — `QUOTE_NOT_FOUND`. Правила, что из наблюдений факт, а что гипотеза, — [методика](../knowledge/ux-review.md).

## Версии формата

`format_version` — целое число, сейчас `1`. Оно есть в `case.json`, каждом реестре, каждом checkpoint и каждой строке журнала; у Markdown версии нет. Поддерживаемые версии перечислены в `versions.json`:

```json
{"current": 1, "supported": [1], "migrations": {}}
```

- Неизвестная версия в `case.json`, реестре или строке журнала: `FORMAT_UNSUPPORTED`, валидатор останавливается и записи не читает.
- Checkpoint с неизвестной или отличной от `case.json` версией проверку не останавливает и ошибок `FORMAT_*` не даёт: он негоден, текущим становится более ранний (`CHECKPOINT_FALLBACK`).
- Известная версия, отличная от версии `case.json`: `FORMAT_MIXED`.
- Нет поля или оно не целое (`1.0`, `true`, строка): `SCHEMA`.

Миграция. Несовместимое изменение формата увеличивает версию. Вместе с новой версией добавляется `tools/migrate_v<N>.py`: он создаёт рядом копию кейса в новом формате, исходная папка не меняется, результат проходит валидатор. В `versions.json` в `migrations` записывается ключ `"<N>"` со ссылкой на скрипт, версия добавляется в `supported`. Изменение контракта согласуется с владельцами зависимых задач в PR. Пока версия одна, скрипта нет.

## Статусы и отзыв

| Тип | Как отзывается | Причина |
|---|---|---|
| `SRC`, `CALC`, `Q`, `OPT` | `record_status`: `active` или `withdrawn` (`SRC` — `tools/evidence.py withdraw`) | при `withdrawn` обязателен `status_reason` |
| `CLM` | `status: withdrawn` (`tools/evidence.py withdraw`) | обязателен `status_reason` |
| `DEC` | `status: superseded` | причина в `change_reason` заменяющего решения |
| `ACT`, `CKP` | не отзываются | — |

Правила связей проверяют только активные записи: отозванные и замещённые остаются в истории и не блокируют кейс. Активная запись не может ссылаться на отозванную (`WITHDRAWN_USED`). Это относится к вариантам, решениям, вопросам, расчётам и ссылкам `[ID]` в `outputs/**/*.md`.

## Записи по типам

Все поля, кроме помеченных необязательными, обязательны. Лишних полей быть не может. У каждой записи реестра есть `id` и `created_at`. Время в реестрах берётся из системных часов в момент записи: команда `date +%Y-%m-%dT%H:%M:%S%:z`.

### Источник `SRC`

```json
{
  "id": "SRC-0001", "created_at": "2026-11-01T10:00:00+03:00",
  "record_status": "active",
  "type": "md", "title": "Заметки о сервисе",
  "location": {"path": "sources/service-notes.md"},
  "origin": "user_provided", "allowed": true,
  "retrieved_at": "2026-11-01T10:00:00+03:00",
  "sha256": "<64 hex>",
  "extraction": {"status": "ok", "complete": true, "limits": "Прочитан целиком."}
}
```

- `type`: `md`, `txt`, `docx`, `pdf`, `csv`, `xlsx`, `web`, `image`. `image` — файл PNG, JPEG или WebP: см. [изображения и наблюдения](#изображения-и-наблюдения).
- `location`: ровно одно из `path` или `url`. Для `url` `sha256` равен `null`, если текст сохранил агент (`add-web`), и равен SHA-256 скачанных байтов, если страницу скачала утилита (`fetch-web`). Для `path` это SHA-256 исходных байтов файла (без перекодировки и нормализации строк; 64 символа, строчные hex). Необязательное `source_url` хранит адрес, откуда скачан файл.
- `origin`: `user_provided`, `public_web`, `own_training`, `synthetic`. `synthetic` — беседа с модельным персонажем: путь вида `sources/interviews/synthetic-<персонаж>-<n>.md` и значение `synthetic` связаны взаимно (иначе `SYNTHETIC_PATH`), утилита чтения выводит `origin` из пути. Синтетический источник не подтверждает ничего: утверждение с ним в `supports` — только `hypothesis` и только `unconfirmed`, он не может быть входом расчёта и не может стоять в `contradicts` (модельное «не согласен» не делает утверждение спорным): всё это `SYNTHETIC_NOT_EVIDENCE`. Синтетичность — свойство происхождения текста, поэтому правило действует и для отозванного источника: беседа, заменённая повтором, не превращает гипотезы из неё в факты и не снимает пометку. `allowed: false` запрещает использовать источник как подтверждение.
- `extraction.status`: `ok`, `partial`, `empty`, `unreadable`, `unsupported`, `over_limit`, `unavailable` (последнее для сайта); `complete` — логическое; `limits` — текст границ чтения.
- Файл источника не меняется после регистрации: другой отпечаток — `SOURCE_CHANGED`, нужна новая запись источника.
- Отзыв: `record_status: "withdrawn"` и `status_reason`.

### Извлечённый текст

`sources/extracted/<SRC-id>.jsonl` создаётся командами `tools/read_material.py add`, `add-web`, `add-observations` и `capture-web`. Одна строка — блок: `n` (номер блока с единицы), `locator` (объект контракта), `text`, необязательные `heading` (ближайший заголовок), `cells` (значения строки таблицы: список для CSV, адрес → значение для XLSX), `formula_no_value` (адреса формул без сохранённого значения). `locator` копируется в `supports`, `contradicts` и `inputs` без изменений, `quote` добавляется при цитировании. При статусах без текста файла нет. Записи `SRC` создаёт эта утилита, руками их не пишут.

### Локатор

Объект с `kind`; указывает точное место в источнике. Необязательное `quote` — короткая цитата.

| `kind` | Поля | Для типов источника |
|---|---|---|
| `section` | `heading` | `md`, `txt`, `docx`, `web` |
| `paragraph` | `index` (с 1) | `docx`, `md`, `txt`, `web` |
| `page` | `page` (с 1) | `pdf` |
| `cells` | `sheet`, `range` | `xlsx` |
| `rows` | `from`, `to` | `csv` |
| `doc_table` | `table`, `row` | `docx`, `web` |
| `region` | `index` (с 1), `area` | `image` |

Индексы начинаются с единицы и считаются по извлечённому тексту: абзац отделён пустой строкой, в DOCX абзац — элемент документа. Другой вид для типа источника — `LOCATOR_MISMATCH`.

Валидатор сверяет локатор с извлечённым текстом источника (`sources/extracted/<SRC-id>.jsonl`) в утверждениях и входах расчётов, только активных:

| `kind` | Подходящие блоки |
|---|---|
| `paragraph`, `page` | у блока такой же индекс |
| `doc_table` | равны `table` и `row` |
| `region` | у блока такой же `index`; `area`, не совпавшая с `area` блока, даёт только предупреждение `REGION_AREA_DIFFERS`; `quote` ищется только в части блока после `Текст:` |
| `section` | `heading` блока равен `heading` локатора |
| `rows` | номер строки блока входит в `from`–`to` |
| `cells` | тот же лист, диапазоны пересекаются; диапазон, который нельзя разобрать, не указывает ни на что |

- Нет подходящего блока — `LOCATOR_NOT_FOUND`. Есть `quote`, но её нет в тексте ни одного подходящего блока — `QUOTE_NOT_FOUND`. Цитата сравнивается с точностью до пробельных символов, регистр важен; склейка соседних блоков не выполняется. Если цитата начинается или кончается числом (цифрой, либо знаком `.` или `,` перед цифрой), рядом не должно быть цифры, знака `.` или `,` с цифрой, а пробел считается разделителем разрядов, когда с одной стороны группа ровно из трёх цифр, с другой от одной до трёх: `140` не совпадает с `1140`, `0.140`, `1 140`, `140 000`, `.140` не совпадает с `0.140`, `,5` — с `140,5`. Фразы `2025 год` и `в 140 случаях` совпадают. Цитата из таблицы должна быть значением одной ячейки: это правило для агента, валидатор проверяет только наличие цитаты в тексте блока.
- Если вид локатора не подходит типу источника, это только `LOCATOR_MISMATCH`. Источники со статусом чтения без текста (`empty`, `unreadable`, `unsupported`, `over_limit`, `unavailable`) не проверяются. Статус источника (в том числе отзыв) на проверку не влияет.
- У источника со статусом `ok` или `partial` нет файла извлечения — предупреждение `EXTRACT_MISSING` (один раз на источник). Файл не разбирается — `FILE_CORRUPT`, прочие проверки для него пропускаются.

### Утверждение `CLM`

```json
{
  "id": "CLM-0001", "created_at": "2026-11-01T11:00:00+03:00",
  "text": "…", "kind": "fact", "status": "confirmed",
  "supports": [{"source_id": "SRC-0001", "locator": {"kind": "section", "heading": "Условия"}, "note": "Что именно подтверждает"}],
  "contradicts": [],
  "derived_from": [],
  "limits": "Только за 2025 год."
}
```

- `kind`: `fact`, `hypothesis`, `forecast`, `inference`. `inference` — вывод из других записей (в том числе прежний ответ модели): он не становится фактом.
- `status`: `confirmed`, `unconfirmed`, `contested`, `withdrawn`. Процент уверенности не записывается.
- `supports`, `contradicts`: списки `{source_id, locator, note}`. У `contradicts` необязательное `resolution` — почему противоречие снято.
- `derived_from`: ID утверждений и расчётов, из которых сделан вывод. `limits`: текст или `null`.
- Подтверждённое (`confirmed`) утверждение: должно быть `fact` или `inference`; у `fact` есть `supports`, у `inference` есть `derived_from`; основание не отозвано, разрешено и читаемо; `derived_from` указывает на подтверждённые утверждения и рассчитанные расчёты; все `contradicts` имеют `resolution`.
- `contested` требует непустого `contradicts`. `withdrawn` требует `status_reason`. Пустое или из одних пробелов `resolution` считается отсутствующим.

Утверждения записываются утилитой `tools/evidence.py` (`add`, `update`, `withdraw`), а не руками: она копирует локатор из блока извлечённого текста, сверяет цитату, проверяет кейс валидатором и при новой ошибке на самом утверждении восстанавливает реестр. Отзыв источника или утверждения понижает зависимые утверждения до `unconfirmed` с пометкой в `limits`; расчёты, варианты, вопросы, решения и тексты `outputs/` утилита только называет. `trace` проходит путь от записи или файла `outputs/` вниз до текста блока, `impact` печатает зависимые записи и файлы. Процедура — [`agent/workflows/evidence.md`](../workflows/evidence.md), методика — [`agent/knowledge/evidence.md`](../knowledge/evidence.md).

### Расчёт `CALC`

```json
{
  "id": "CALC-0001", "created_at": "…", "record_status": "active",
  "inputs": [{"name": "заявки", "source_id": "SRC-0002", "locator": {"kind": "rows", "from": 2, "to": 13}, "column": 2, "aggregate": "sum", "value": 1440, "unit": "заявок", "period": "2025-01..2025-12"}],
  "method": {"kind": "tool", "description": "Среднее число заявок в месяц", "formula": "заявки / 12", "digits": 6},
  "result": {"status": "computed", "value": 120, "unit": "заявок в месяц", "period": "2025"},
  "gaps": [], "assumptions": [],
  "reproduce": "tools/calc.py check projects/<case-id> CALC-0001"
}
```

- Вход расчёта — либо `{name, source_id, locator, value, unit, period}`, либо `{name, calculation_id, value, unit, period}` для результата другого расчёта; ID проверяются как остальные ссылки.
- Необязательные поля входа из источника: `aggregate` (`value`, `sum`, `mean`, `min`, `max`, `count`) — как свёрнуты ячейки диапазона; `column` — номер столбца CSV с 1 (у XLSX столбец задан диапазоном `cells` в одном столбце). Вход-число из текста хранит локатор блока с `quote`, в которой ровно одно число.
- `method.kind`: `tool` или `formula`. `method.formula` — арифметика над именами входов (`+ - * /`, скобки, числа), `method.digits` — знаки округления результата, 0–10, по умолчанию 6, половина вверх. `reproduce` — команда от корня репозитория без личных путей (абсолютный путь — `PATH_UNSAFE`) либо формула.
- `result.status`: `computed` (значение — число) или `not_computable` (значение `null`). `value`, `unit`, `period` неизвестных данных — `null`.
- Запись с `method.formula` валидатор пересчитывает: значения входов из извлечённого текста и результатов входящих расчётов, затем формулу. Арифметика идёт в десятичных числах, поэтому сумма долей, равная целому, даёт ровно ноль. Расхождение — `CALC_MISMATCH`. Рассчитанная запись без формулы либо вход без извлечённого текста — предупреждение `CALC_UNVERIFIED`. Новые поля необязательны, поэтому `format_version` остаётся 1.

Расчёты записываются утилитой `tools/calc.py` (`add`, `check`), отзываются `tools/evidence.py withdraw`. Процедура — [`agent/workflows/calculations.md`](../workflows/calculations.md), методика — [`agent/knowledge/calculations.md`](../knowledge/calculations.md).

### Вопрос исследования `Q`

Поля: `record_status`, `question`, `affects` (какой выбор зависит от ответа), `needed_evidence`, `status` (`open`, `answered`, `partial`, `blocked`), `findings` (ID утверждений и расчётов), `gap` (текст или `null`).

### Вариант `OPT`

Поля: `record_status`, `title`, `strategy_kind` (`keep`, `close`, `develop`), `audience_task`, `action`, `rejected_actions` (список), `benefit_mechanism`, `economics` (текст; неизвестное названо неизвестным, числа не выдумываются), `preconditions` (список), `objections` (непустой список), `risks` (список), `reversibility`, `verification`, `basis` (ID утверждений и расчётов). Пустой `basis` допустим, но даёт предупреждение `BASIS_UNCONFIRMED`.

### Решение `DEC`

```json
{
  "id": "DEC-0002", "created_at": "…", "topic": "direction", "status": "chosen",
  "proposal": {"option_id": "OPT-0003", "rationale": "…", "proposed_at": "…", "action_id": "ACT-0008"},
  "choice": {"option_id": "OPT-0001", "user_statement": "Слова пользователя", "chosen_at": "…", "action_id": "ACT-0009"},
  "supersedes": "DEC-0001",
  "change_reason": "Пользователь изменил ограничение"
}
```

- `status`: `proposed` (есть только `proposal`), `chosen` (есть `choice`), `superseded` (заменено). Заменённая запись прежде была предложением или выбором, поэтому без `proposal` и `choice` её не бывает: недействительность прежнего выбора выражает новая запись с `supersedes`, а не пустая запись. Нарушение — `DECISION_CHOICE_STATE`.
- `proposal` равно `null`, если решение принял сам пользователь без предложения агента: такая запись сразу `chosen`. Необязательные `supersedes` и `change_reason` без значения не пишутся.
- `choice.option_id` равно `null`, если выбор не относится к варианту: `topic: brief` — утверждение брифа, `topic: budget` — расширение бюджета исследования, `topic: interview_method` — способ бесед с модельными клиентами (гайд и персонажи), `topic: thresholds` — согласование порогов плана проверки, `topic: commitments` — согласование документа `outputs/commitments.md`, `topic: revision` — выбор человека после новых данных (`user_statement` — его слова). Записи о порогах, обязательствах и пересмотре создаются только после ответа человека, сразу `chosen`, с `proposal: null`. Новое согласие или следующий пересмотр заменяет прежнюю запись через `supersedes`. Для `topic: direction` это ошибка `DECISION_CHOICE_STATE`. `proposal.option_id` всегда ссылается на вариант.
- Предложение модели и выбор человека разделены. `proposal.action_id` — действие `model`; `choice.action_id` — завершённое действие `human_input`, в `result_refs` конца которого есть это решение. Иначе `DECISION_NOT_HUMAN`. Выбор может отличаться от предложения.
- `choice.delegated: true` — человек передал выбор агенту («реши сам»). Тогда `choice.option_id` совпадает с `proposal.option_id`: под видом передачи нельзя выбрать другой вариант, чем рекомендован. Действие предложения в журнале заканчивается раньше, чем начинается действие человека: передать можно только уже показанную рекомендацию. Иначе `DECISION_CHOICE_STATE`. Поле пишется только со значением `true`.
- `proposed` становится `chosen` на месте: добавляется `choice`. Если меняется предложение или уже сделанный выбор, создаётся новая запись с `supersedes` и `change_reason`, прежняя получает `superseded` (`DECISION_SUPERSEDE`). Замены не образуют цикл.
- `topic` — короткий идентификатор предмета решения: строчные латинские буквы, цифры и `_`, начинается с буквы (`direction` в обязательном сценарии). Замена не меняет `topic`; одну запись заменяет не больше одной (ветвление — `DECISION_SUPERSEDE`). На один `topic` приходится ровно одна незаменённая запись, считая `proposed` (`DECISION_MULTIPLE_ACTIVE`).

### Действие `ACT`

Журнал `state/actions.jsonl` — по строке JSON на событие, у действия две строки:

```json
{"format_version": 1, "id": "ACT-0007", "phase": "start", "kind": "web_read", "tool": "WebFetch", "environment": "claude_code", "model": "…", "input_refs": ["SRC-0002"], "at": "…"}
{"format_version": 1, "id": "ACT-0007", "phase": "end", "outcome": "completed", "result_refs": ["SRC-0002"], "cost": {"basis": "unknown"}, "at": "…"}
```

- `kind`: `model`, `search`, `web_read`, `file_read`, `compute`, `save`, `human_input`. `environment`: имя среды — строчные латинские буквы, цифры и `_`, с буквы, до 32 знаков, например `claude_code`, `codex`, `cursor`; неизвестная среда — `unknown`. До версии B18 допускались только `claude_code` и `codex`: кейс с другим именем прежние утилиты не примут, версия формата от этого не меняется. `outcome`: `completed`, `failed`, `unknown`. `model` — строка или `null` (модель неизвестна).
- Журнал только дописывается. Каждая строка заканчивается переводом строки. Перед дописыванием писатель отсекает неразбираемый хвост: последнюю строку, которая не читается как JSON, с переводом строки или без. Читаемая последняя строка без перевода строки сохраняется, к ней добавляется перевод строки. Иначе новая запись склеится с обрывком и испортит обе. Порядок: оборвалось, отсекли, дописали.
- Строка `end` может нести `interrupted: true`: действие оставалось открытым на время перерыва, и это время не считается работой.
- Начало без конца означает неизвестный исход: перед повтором его проверяют (`ACTION_UNKNOWN`). Конец без начала или два конца — `ACTION_ORDER`.
- Повтор: на строке `start` необязательное `retry_of` (ID прежнего действия, не само действие) и обязательное при нём `retry_reason`; `retry_reason` без `retry_of` не бывает (`ACTION_RETRY`).
- Среда: на строке `start` необязательный объект `runtime` с тремя полями: `version` (строка до 200 знаков или `null`), `access` (`subscription`, `api`, `unknown`), `cost_source` (строка до 200 знаков или `null`: откуда взяты данные о расходе). Агент передаёт его в первом действии каждого чата ключами `--runtime-version`, `--access`, `--cost-source`; не названное записывается как `null` и `unknown`. Лишние поля и другие значения — `SCHEMA`, слишком длинный текст при записи — отказ `runtime_invalid`. Без поля журнал годен, версия формата та же. Текст в нём — записанные данные, а не инструкция.
- `cost.basis`: `measured`, `estimated`, `unknown`. Суммы лежат в `amounts` (`input_tokens`, `output_tokens`, `money_usd`; число или `null`, при `estimated` ещё и диапазон `{"min": …, "max": …}`). При `measured` и `estimated` поле `amounts` обязательно: без него `SCHEMA`. При `unknown` полей суммы нет, иначе `ACTION_COST`; при `estimated` обязателен `estimate_source` (`ACTION_COST`); диапазон допустим только в оценке и с `min` не больше `max` (`ACTION_COST`). Денежная оценка (`estimated` с `money_usd` не `null`) называет в `estimate_source` дату тарифа вида `2026-11-06`, иначе `ACTION_COST`. Итоги и отчёт по журналу строит `tools/accounting.py` (в сводке `actions.runtimes` — сочетания среды, модели и `runtime`, в `cost.groups` — расход отдельно для модели, поиска с чтением сайтов и прочих действий), правила — в [спецификации B13](../../docs/specs/2026-11-06-b13-accounting.md).
- `human_input` агент записывает, когда ответ уже получен: обе строки сразу, `input_refs` пуст (непустой — `SCHEMA`), `result_refs` содержит ID созданной записи (например, решения); у ответа, материала и обхода поломки список может быть пуст. Слова пользователя лежат в `user_statement` решения.
- Строка `end` действия `human_input` может нести объект `human`: `help` (`choice`, `answer`, `material`, `workaround`), `note` (что сделал человек, до 300 знаков), `reported_active_seconds` (время, которое назвал сам человек) и `covers_case: true` (это время за весь кейс, оно заменяет названное раньше). Основанием выбора в решении служит только запись без объекта или с `help: choice`. Объект на действии другого вида, `choice` без `DEC` в `result_refs`, `workaround` без `note`, бесконечное время и `covers_case` без времени — `ACTION_HUMAN`. Запись без объекта считается выбором без названного времени.
- Незавершённая последняя строка (обрыв записи) игнорируется с предупреждением `JOURNAL_TORN`; неразбираемая строка не в конце — `FILE_CORRUPT`.

### Checkpoint `CKP`

```json
{
  "format_version": 1, "id": "CKP-0002", "case_id": "demo-case",
  "created_at": "…", "seq": 2, "previous": "CKP-0001",
  "goal": "…", "stage": "strategies",
  "artifacts": [{"path": "outputs/product-strategy.md", "sha256": "<64 hex>"}],
  "completed_actions": ["ACT-0001"], "human_choices": ["DEC-0002"],
  "open_items": ["…"], "next_step": "…",
  "totals": {"elapsed_seconds": 3600, "time_to_first_result_seconds": 600, "human_active_seconds": null, "cost": {"basis": "unknown"}}
}
```

- `stage`: `intake`, `research`, `options`, `decision`, `strategies`, `validation_plan`, `done`. `previous` — ID прежнего checkpoint либо `null`; `seq` растёт на единицу от `previous`. `totals`: `elapsed_seconds`, `time_to_first_result_seconds` и `human_active_seconds` (число либо `null`), `cost` по правилам учёта действий.
- Отпечаток артефакта служит его версией. Checkpoint записывается новым файлом после записи и проверки артефактов; порядок и атомарность описаны в разделе «`save`» [спецификации B06](../../docs/specs/2026-11-06-b06-checkpoint.md) и в [процедуре](../workflows/checkpoint.md), запись выполняет `tools/checkpoint.py`.
- Негодный checkpoint: неразбираемый, с нарушением схемы или версии, чужим `case_id`, `id`, не совпавшим с именем файла, отсутствующим артефактом, неверным учётом или нарушением цепочки (`previous` не найден либо `seq` не на единицу больше). Имя файла — только `CKP-NNNN.json`; любой другой файл в `state/checkpoints/` (кроме скрытых, начинающихся с точки) считается негодным. Скрытые `.lost-CKP-…` (потерянный негодный файл, признанный пользователем) и `.rejected-CKP-…` (опубликованный, но не прошедший повторную проверку) — служебные: содержимое сохраняется, валидатор их пропускает, номера в них не используются повторно, а ссылка на такой ID из журнала не даёт `ID_MISSING`. Текущий — годный с наибольшим `seq`. Отдельного указателя нет.
- Текущий checkpoint не должен называть выбором человека решение без `choice` и завершённым — действие без исхода `completed`: это ошибка `CHECKPOINT_CLAIM`.
- Другой отпечаток артефакта не делает checkpoint негодным, а даёт предупреждение `CHECKPOINT_STALE` со списком файлов: агент сверяет их и сохраняет новый checkpoint.
- Потерянным считается негодный файл с номером больше номера `previous` текущего checkpoint (0, если `previous` — `null`) и посторонний файл. Если файл `previous` существует, но не читается, `seq` с ним не сравнивается. Если новейший негоден, текущим становится более ранний, и выводится `CHECKPOINT_FALLBACK` с причинами и номерами потерянных файлов (для негодного файла номер берётся из имени, поэтому потеря новейшего видна всегда; посторонние файлы тоже названы в предупреждении). Если негодны все — ошибка `CHECKPOINT_NONE_VALID`. Кейс без checkpoint допустим.

### Тексты `outputs/**/*.md`

Ссылки на записи пишутся в квадратных скобках: `[CLM-0001]`, `[CALC-0002]`, `[OPT-0001]`; несколько ID в одной скобке — через запятую: `[CLM-0001, CLM-0002]`. Ссылка на несуществующую запись либо на `ACT` или `CKP` — `OUTPUT_LINK`. Скобка, которая выглядит как ссылка, но написана неверно (строчные буквы, меньше четырёх цифр), — тоже `OUTPUT_LINK`. Проверяются файлы во всех подпапках `outputs/`, кроме тех, чьё имя или имя папки начинается с точки. Ссылка на отозванную — `WITHDRAWN_USED`; на неподтверждённое или спорное утверждение — допустимо, но даёт предупреждение `BASIS_UNCONFIRMED`. Исключение — `outputs/revisions.md`: журнал только дописывается, и позже названная в нём запись может быть отозвана или замещена. Для журнала проверяется только то, что ссылка записана верно и запись существует; `WITHDRAWN_USED` и `BASIS_UNCONFIRMED` для него не выдаются.

Обязательная структура файлов и строка статуса проверяются утилитой `tools/gate.py`, а не валидатором: незаконченный этап не является ошибкой кейса.

| Файл | Разделы второго уровня |
|---|---|
| `outputs/options.md` | `Что известно`, `Чего не хватает`, `Сравнение вариантов`, `Рекомендация`, `Что изменит рекомендацию` |
| `outputs/product-strategy.md` | `Аудитория и задача`, `Текущие альтернативы`, `Выбранное направление`, `Отказы`, `Ценность`, `Затраты и доходы`, `Допущения и ограничения` |
| `outputs/communication-strategy.md` | `Аудитория и ситуация`, `Барьер`, `Ключевое сообщение`, `Подтверждение`, `Роль каналов`, `Границы обещаний`, `Обещания и возможности`; при `close` ещё `Завершение и последствия`, при `keep` ещё `Почему без изменений и условия пересмотра` |
| `outputs/validation-plan.md` | `Ожидаемое изменение`, `Показатель и единица`, `Исходное состояние`, `С чем сравниваем`, `Период наблюдения`, `Условие успеха и неуспеха`, `Нежелательные последствия` |
| `outputs/commitments.md` | `Решение`, `Действия`, `Обязательства`, `Условия пересмотра`, `Согласование` |

Строка статуса стоит сразу после заголовка файла во всех файлах, кроме `options.md` и `revisions.md`: `Статус: выбор сделан [DEC-…], вариант [OPT-…]` либо `Статус: предварительно, выбор не сделан, предложен вариант [OPT-…]`. Пометка `(допущение)` после числа означает, что оно не из материалов и не от пользователя. `[бриф]` в строке означает, что число названо в разделе `Слова пользователя` брифа: оно сверяется с этим разделом точно, вместе с единицей. Числа сверяются построчно: строка таблицы, абзац или пункт списка. Год не сверяется, только если рядом слово «год» или «г.». Знак сравнивается, только если записан в тексте.

Раздел `Действия` в `outputs/commitments.md` — таблица с колонками `Действие`, `Ответственный`, `Срок`, `Показатель`, `Основание`. Заполнены все пять ячеек, в `Основание` есть ссылка. Срок либо названный пользователем (`[бриф]`), либо с пометкой `(допущение)`. Каждое условие в `Условия пересмотра` содержит ссылку на утверждение, расчёт или решение. Раздел `Согласование` ссылается на действующее решение `commitments`, пока его нет, документ ждёт согласия.

### Журнал пересмотров `outputs/revisions.md`

Заголовок файла `# Пересмотры`, затем записи по порядку, новые в конце. Номер в заголовке идёт подряд с 1, в том числе для записей «изменений нет». Каждая запись:

```markdown
## Пересмотр 2 — 2026-11-20

- Новые данные: [SRC-0014]
- Изменилось: [CLM-0007] было «…», стало «…» [CLM-0031]
- Условия пересмотра: сработало «…» | не сработало ни одно
- Затронуто: product-strategy.md «Ценность»; commitments.md «Действия»; [CALC-0004]
- Не затронуто: communication-strategy.md; validation-plan.md
- Выбор: [DEC-0012] | изменений нет
- Прежние версии: outputs/.history/2/ | нет
```

Формат журнала проверяется всегда, когда файл есть, даже без решений `revision`. Все семь строк обязательны, каждая встречается один раз. Каждое решение `revision` в статусе `chosen` или `superseded` названо в строке `Выбор` ровно одной записи. У записи с решением есть папка `outputs/.history/<N>/` с файлами, а в `Прежние версии` стоит её путь; запись «изменений нет» снимка не требует и пишет `нет`. Если запись называет `validation-plan.md` или `commitments.md` в строке `Затронуто`, согласие с порогами или обязательствами должно быть дано не раньше последнего такого решения `revision`.

`tools/revision.py affected` разбирает только файлы `outputs/*.md` (не подпапки), без `revisions.md` и `accounting.md`: отчёт об учёте переписывает шаг учёта, а не пересмотр. Строка статуса сама по себе затронутым разделом не считается.

## Проверка этапа

```text
.venv/Scripts/python.exe tools/gate.py check projects/<case-id> <этап> [--preliminary]
```

Этапы: `research`, `options`, `decision`, `strategies`, `validation_plan`, `done`. Проверка накопительная и ничего не пишет. Первая строка вывода — JSON с `passed`, `problems` и `warnings`, элементы содержат код, файл, ID и пояснение без текста материалов. Коды выхода: 0 пройдено, 1 найдены проблемы, 4 отказ, 5 сбой. Ошибки валидатора прекращают проверку одним кодом `CASE_INVALID`. `--preliminary` допустим для `strategies` и `validation_plan`.

| Код | Условие |
|---|---|
| `RESEARCH_EMPTY`, `RESEARCH_OPEN`, `RESEARCH_NO_FINDING`, `RESEARCH_NO_GAP`, `RESEARCH_HIDDEN_CONFLICT` | нет вопросов, вопрос открыт, ответ без оснований, пробел не назван, спорное основание без пробела |
| `OPTIONS_TOO_FEW`, `OPTIONS_NO_KEEP`, `OPTIONS_NO_CLOSE`, `OPTIONS_NO_DEVELOP`, `OPTIONS_DUPLICATE`, `OPTION_FIELD_EMPTY`, `OPTIONS_TABLE` | требования к набору и полям вариантов, вариант не в таблице сравнения |
| `PROPOSAL_MISSING`, `DECISION_PENDING` | нет решения `direction`, нет выбора человека |
| `OUTPUT_MISSING`, `OUTPUT_SECTION`, `STATUS_LINE`, `WRONG_OPTION`, `SECTION_UNLINKED`, `PRELIMINARY_LEFT` | структура файла, статус, связь с выбором, раздел с выводом без ссылки, предварительный статус на `done` |
| `PROMISE_TABLE`, `PROMISE_WEAK`, предупреждение `PROMISE_PLANNED` | таблица обещаний, основание неподтверждённое, основание только выбранный вариант |
| `NUMBER_UNLINKED`, `NUMBER_MISMATCH`, `NUMBER_AMBIGUOUS` | число без ссылки, не совпадает с записью или брифом, знак не читается |
| `INTERVIEW_METHOD_MISSING` | есть активный синтетический источник или `outputs/interview-guide.md`, а действующего решения `interview_method` в статусе `chosen` нет; либо источник создан раньше первого выбора способа. Повторный выбор (новое решение `interview_method` через `supersedes`) не отменяет прежние беседы: срок отсчитывается от самого раннего решения по цепочке `supersedes` |
| `INTERVIEW_GUIDE` | `outputs/interview-guide.md`: нет статус-строки `Статус: способ выбран [DEC-…]` либо она не ссылается на действующее решение `interview_method`; нет ни одного раздела `Q-NNNN. …`; раздел `Q-NNNN. …` неверного вида, с несуществующим `Q` или с `Q` не в статусе `partial` или `blocked`. Разделы `Кого спрашивать` и `Согласие и данные` и числа проверяются кодами `OUTPUT_SECTION` и `NUMBER_*` |
| `INTERVIEW_LIMIT` | больше трёх активных синтетических источников без решения `budget` в статусе `chosen`, принятого после первого выбора способа (самого раннего решения `interview_method` по цепочке `supersedes`, повторный выбор срок не сдвигает); считаются только активные источники, заменённая повтором беседа отозвана и не в счёт; либо больше десяти разделов `## Вопрос N` в одной беседе |
| `SYNTHETIC_UNMARKED` | в `outputs/options.md`, `product-strategy.md`, `communication-strategy.md`, `validation-plan.md` или `commitments.md` ссылка на утверждение или расчёт с синтетическим основанием (в `supports` синтетический источник, в том числе отозванный, транзитивно через `derived_from` и входы расчёта) без пометки `(синтетика)` сразу после ссылки; ссылки на варианты пометки не требуют |
| `THRESHOLDS_PENDING`, `THRESHOLDS_NOT_CITED`, `ACTIONS_OPEN` | пороги не согласованы либо согласованы раньше текущего выбора, `outputs/validation-plan.md` не ссылается на действующее решение `thresholds`, действие начато и не закрыто |
| `COMMITMENTS_PENDING` | на `done`: нет действующего решения `commitments` с выбором человека, либо оно принято раньше текущего выбора направления |
| `COMMITMENTS_NOT_CITED` | раздел `Согласование` в `outputs/commitments.md` не ссылается на действующее решение `commitments` |
| `COMMITMENTS_TABLE` | таблица `Действия`: другие колонки, нет строк, в строке пустая ячейка или нет ссылки в `Основание` |
| `REVIEW_UNLINKED` | условие пересмотра в `outputs/commitments.md` без ссылки |
| `REVISION_FORMAT` | `outputs/revisions.md`: нет заголовка `# Пересмотры`, неверный заголовок записи, не хватает или повторяется строка записи, `Выбор` или `Прежние версии` не в допустимой форме |
| `REVISION_NUMBER` | номера записей идут не подряд с 1 |
| `REVISION_UNRECORDED` | есть решение `revision`, а журнала нет, либо решение названо не ровно в одной записи |
| `REVISION_NO_SNAPSHOT` | у записи с решением нет непустой папки `outputs/.history/<N>/` |
| `REAPPROVAL_PENDING` | пересмотр затронул `validation-plan.md` или `commitments.md`, а действующее решение `thresholds` или `commitments` принято раньше этого пересмотра |

## Валидатор

```text
.venv/Scripts/python.exe tools/validate_project.py <папка кейса> [--json]
```

Код выхода: `0` — ошибок нет, `1` — есть ошибки, `2` — неверный вызов, `3` — внутренний сбой валидатора: текст исключения не печатается (там могут оказаться данные кейса), а с `--json` выводится объект с `"internal_error": true`. Вывод содержит код, файл, ID записи и короткое пояснение, без содержимого полей и материалов. `--json` печатает `{"errors": [...], "warnings": [...], "current_checkpoint": "CKP-0002"}`; элемент списка — `{"code", "file", "record_id", "message"}`, `current_checkpoint` — ID текущего checkpoint или `null`. Файл checkpoint — `state/checkpoints/<ID>.json`. Валидатор только читает.

### Коды ошибок

| Код | Условие |
|---|---|
| `ID_DUPLICATE` | ID повторён в кейсе |
| `ID_MISSING` | ссылка на несуществующий ID |
| `ID_WRONG_TYPE` | ссылка на запись другого типа |
| `CLAIM_NO_BASIS` | `confirmed` без `supports`; `inference` без `derived_from` при любом статусе |
| `SOURCE_MISSING` | файл активного источника отсутствует |
| `SOURCE_CHANGED` | отпечаток файла активного источника другой |
| `CLAIM_WEAK_SOURCE` | основание `confirmed` — отозванный, запрещённый или нечитаемый источник |
| `CLAIM_WEAK_DERIVATION` | `confirmed` опирается на запись не в статусе `confirmed`, на нерассчитанный расчёт на расчёт от слабого источника (включая цепочку расчётов) либо на самого себя через цепочку `derived_from` |
| `CLAIM_CONFLICT_HIDDEN` | `confirmed` при `contradicts` без `resolution` |
| `CLAIM_NOT_CONTESTED` | `contested` без `contradicts` |
| `FACT_NOT_CONFIRMABLE` | `confirmed` при `kind` не `fact` и не `inference` |
| `STATUS_NO_REASON` | отзыв без `status_reason` |
| `LOCATOR_MISMATCH` | вид локатора не подходит типу источника |
| `LOCATOR_NOT_FOUND` | у источника есть извлечённый текст, но локатор не указывает ни на один блок |
| `QUOTE_NOT_FOUND` | `quote` нет в тексте блоков, на которые указывает локатор |
| `WITHDRAWN_USED` | активная запись или текст `outputs/**/*.md` ссылается на отозванную |
| `DECISION_CHOICE_STATE` | `chosen` без `choice`, `proposed` с `choice`, запись без `proposal` и `choice`, выбор направления без варианта либо переданный агенту выбор не того варианта, что предложен |
| `DECISION_NOT_HUMAN` | выбор не опирается на завершённое `human_input` либо предложение не на `model` |
| `DECISION_SUPERSEDE` | замена без причины, заменённое не `superseded`, `superseded` без замены, цикл, ветвление, смена `topic` |
| `DECISION_MULTIPLE_ACTIVE` | больше одной незаменённой записи на `topic` |
| `ACTION_RETRY` | `retry_of` без `retry_reason`, `retry_reason` без `retry_of`, повтор самого себя |
| `ACTION_ORDER` | конец без начала либо два конца |
| `ACTION_COST` | суммы при `unknown`, `estimated` без `estimate_source`, неверный диапазон, денежная оценка без даты тарифа |
| `ACTION_HUMAN` | `human` не на `human_input`, выбор без `DEC`, обход поломки без `note`, бесконечное время, итог за кейс без времени |
| `OUTPUT_LINK` | ссылка в `outputs/**/*.md` на несуществующую запись, на `ACT`, `CKP` либо скобка, похожая на ссылку, но неверная |
| `PATH_UNSAFE` | абсолютный путь, обратная косая черта, выход за корень, источник вне `sources/`, `url` не `http`/`https`, абсолютный путь в `reproduce` |
| `SCHEMA` | нарушение схемы, неверная дата, значение ID с посторонними символами |
| `FORMAT_UNSUPPORTED`, `FORMAT_MIXED` | версия формата |
| `CASE_INVALID` | нет `case.json` либо `case_id` не совпадает с папкой |
| `FILE_CORRUPT` | файл не разбирается как JSON (в UTF-8) |
| `TIME_IN_FUTURE` | `created_at`, `proposed_at` или `chosen_at` записи реестра позже текущего времени больше чем на пять минут |
| `SYNTHETIC_NOT_EVIDENCE` | синтетический источник (в том числе отозванный) в `supports` утверждения не `hypothesis` или `confirmed`, в `contradicts` любого утверждения либо входом расчёта |
| `SYNTHETIC_PATH` | `origin: synthetic` вне `sources/interviews/synthetic-*` либо такой путь с другим `origin` |
| `CALC_MISMATCH` | активный расчёт с `method.formula` не следует из входов: значение входа расходится с материалом или с результатом входящего расчёта, результат — с формулой; не выдаётся при уже найденной ошибке ссылки, локатора, цитаты или отзыва этой записи |
| `CHECKPOINT_NONE_VALID` | все checkpoint негодны |
| `CHECKPOINT_CLAIM` | текущий checkpoint называет выбором человека решение без `choice` либо завершённым действие без исхода `completed` |

Предупреждения не меняют код выхода: `BASIS_UNCONFIRMED`, `SOURCE_PARTIAL`, `EXTRACT_MISSING`, `ACTION_UNKNOWN`, `JOURNAL_TORN`, `CHECKPOINT_STALE`, `CHECKPOINT_FALLBACK`, `CALC_UNVERIFIED` (рассчитанный расчёт без `method.formula`: число записано вручную; либо у входа расчёта нет извлечённого текста, и формула проверена только по записанным значениям входов), `REGION_AREA_DIFFERS` (в локаторе `region` область не та, что в наблюдении с этим номером).

Если реестр или журнал не читается (`FILE_CORRUPT`, нарушена общая форма файла), ссылки на записи его типа не проверяются, чтобы одна ошибка не порождала лавину.

## Примеры

`examples/valid/demo-case/` — полный завершённый кейс: по записи каждого типа, отозванное утверждение, снятое противоречие, замещённое решение, действие с неизвестным расходом, два checkpoint, документы всех этапов с согласованными порогами и обязательствами, отчёт учёта и один записанный пересмотр со снимком в `outputs/.history/1/`. `tools/gate.py check` проходит на нём этап `done`. Файл `examples/valid/expected-warnings.json` перечисляет предупреждения образца тройками `code`, `file`, `id` (сейчас одно стоячее `BASIS_UNCONFIRMED` на ссылку в `outputs/commitments.md` на гипотезу из синтетической беседы).

`examples/invalid/<случай>/` содержит нарушение одного правила как наложение на `valid/demo-case/`:

- `expected.json` — `{"errors": ["КОД"], "warnings": []}`: точный набор ожидаемых кодов; необязательное `"delete": ["путь/от/корня/кейса"]` — файлы образца, которые убираются; необязательное `"supported_versions": [1, 2]` — версии, считающиеся поддерживаемыми в этом тесте;
- остальные файлы папки повторяют путь от корня кейса и заменяют файлы образца целиком.

Тест собирает образец и наложение во временную папку `demo-case` (имя должно совпадать с `case_id`) и запускает валидатор. Хэши файлов в примерах зависят от байтов, поэтому для `agent/contracts/examples/` в `.gitattributes` отключены преобразования строк.
