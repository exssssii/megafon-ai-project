Агент сказал, что окружение ссылается на отсутствующий Python, и дальше работал на встроенном Python Codex, подставив `PYTHONPATH` на пакеты `.venv`. Результат получен на непроверенном пути.
- В полных прогонах этого не видно: там `--approve-for-me` одобряет выход из песочницы.
- Подгрузились личный `~/.codex/AGENTS.md` и личные плагины. Агент в каждом ходе читал чужие навыки. Проход не чистый.

## Исправления

| Что | Правка | Проверено |
|---|---|---|
| Python в песочнице Codex | START и README: на Windows подготовка `$env:UV_PYTHON_INSTALL_DIR = "$PWD\.python"` и `uv sync --locked --managed-python`. `pyproject.toml`: `link-mode = "copy"`, `.python/` в `.gitignore`. Python и пакеты лежат в папке проекта, без ссылок на кеш `uv` в профиле | `codex sandbox` без модели, на распакованном архиве. Python из профиля — отказ. Python в папке, пакеты жёсткими ссылками на кеш — `Permission denied` при импорте. Python в папке и копии пакетов — валидатор и чтение DOCX с кодом 0. Команда из START пересобирает `.venv`, собранный на системном Python. Последующий `uv sync --locked` его сохраняет |
| Подмена интерпретатора | `intake.md`, `read-materials.md`: если Python из `.venv` не запускается, другой не подставлять, а попросить выполнить подготовку из START | Не проверено живьём |
| Английский и номера в промежуточных сообщениях | `product-mode.md`: весь видимый текст на языке пользователя, без служебных слов и номеров. Перед строкой режима в итоговом сообщении ничего нет | Не проверено живьём |
| Команда `codex` не найдена | START и README: как найти `codex.exe` | Команда выполнена при проходе |
