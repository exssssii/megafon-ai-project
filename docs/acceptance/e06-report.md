# Отчёт о сравнении с обычным чатом (E06)

Связь: [протокол E06](e06-protocol.md), [карточка E06](../tasks/IMPROVEMENTS.md#e06-сравнение-с-исходным-способом), [отчёт B12](b12-report.md), [доработки](../tasks/POLISH.md).

## Итог

Во всех четырёх ячейках оба судьи ответили, что руководителю меньше пришлось бы исправлять результат агента. В трёх ячейках после сверки у агента нет ни существенных ошибок, ни пропусков, а у чата их 1–2. В Claude Code × `retention-smb` счёт по мере протокола равный, 2 на 2. Ошибки там разные: у агента одно неверное контрольное число и неверное описание периода, у чата причина ухода выдана за установленный факт и нет стратегий под выбранный вариант.

Главное различие — продолжение после перерыва. Оба чата Codex после нового разговора потеряли выбор руководителя и продолжили работу под другой вариант. Ни один агент выбор не потерял. Чаты Claude Code выбор сохранили, но не написали полной пары стратегий под выбранный вариант.

Агент работает в 4,8–5,5 раза дольше чата в Claude Code и в 2,0–2,1 раза дольше в Codex. Расход у агента в 6,2–6,6 раза больше в Claude Code и в 5,3–6,1 раза больше по входным токенам в Codex. Прежние числа расхода были суммой накопленных значений реплик и завышали его примерно в 3–5 раз, в отчёте они исправлены. По одному прогону на ячейку, статистической значимости нет.

Сравнение измерено на версии PR №42. Сдаваемая версия отличается от него правками, найденными в этом сравнении и в B12: номера записей в ответах, период оттока, остановка на вопросе о способе, реплика `c3-2a`, отчёт о следах `..` и о субагентах Codex. Каждая правка проверена коротким прогоном, а не повтором сравнения ([правки после PR №42](b12-report.md#правки-после-8bebdc7)). Судьи эти версии не оценивали.

В Codex × `retention-smb` судья Claude насчитал у чата одну ошибку без пропусков, судья Codex — четыре ошибки и один пропуск. Ниже разобрано, что из этого подтвердилось.

Что осталось после сверки:

- **Claude Code × `retention-smb`, агент.** Вклад одиночек «795,6 тыс. руб.» вместо контрольных 789 100 ₽: оба судьи. Апрель–сентябрь назван месяцами, «когда обращения о сбоях вернулись к обычному уровню», хотя в апреле было 48 обращений против 11–19 в остальные месяцы и агент сам это писал: судья Codex, подтверждено по досье. Отдельно судья Claude отметил, что порог «разница оттока не менее 3 п.п.» выше возможного эффекта 2,9 п.п. Это не ошибка по списку, но руководителю пришлось бы это исправить.
- **Claude Code × `retention-smb`, чат.** «Отток вырос из-за повышения тарифа… а не из-за мартовского сбоя» — гипотеза, выданная за факт: оба судьи. Судья Codex разбил это утверждение на три ошибки, при сверке оно засчитано одной. Пропуск K8: оба исполнителя согласны, что стратегий под выбранный вариант нет. Чат сам пишет, что новых стратегий не писал.
- **Claude Code × `direction-b2c`, чат.** Пропуск K8: нет коммуникационной стратегии. По K5 судьи разошлись: судья Codex поставил «нет», судья Claude — «частично». Принято «частично»: «закрыть» в сравнении есть, а «оставить как есть» нет. «Масштабировать чат как есть» меняет объём, это не текущее состояние. Вне списка: в шапке `thresholds.md` написано «согласовано», а в тексте — «Все числа ниже мои предложения, не согласованы». Правило `c3-2a` чат применил к условию «прибыль за месяц», а не к отказу клиники.
- **Codex, чат, оба кейса.** После перерыва потерян выбор руководителя: в `retention-smb` вместо варианта A вернулся рекомендованный B, в `direction-b2c` вместо варианта 2 появился «малый продукт». Пропуск K11: выбор не восстановлен в `c3-1`. В `retention-smb` судья Claude поставил K11 «частично». Принято «нет», как у обоих судей в `direction-b2c` при той же потере.

Что при сверке не подтвердилось:

- **Округление контрольных чисел.** Судья Codex считал ошибками «2,682 млн ₽» против 2 681 670, «2,361 млн ₽» против 2 361 270, «762,9 тыс. ₽» против 762 930 и «около 790 тыс. ₽» против 789 100: допуск в контрольном файле 50 и 1 ₽. При сверке это не засчитано: значение верно с той точностью, с которой оно показано. Неверное число получается из другого расчёта, как 795,6 против 789,1. Такое правило применено одинаково к агенту и к чату, но это решение человека, а не буква протокола. По букве у чатов Claude Code и Codex × `retention-smb` ошибок было бы на две и три больше.
- **Claude Code × `direction-b2c`, агент.** Судья Codex засчитал ошибкой, что стратегия написана вопреки просьбе их не писать: в `c3-1` агент сам так сказал. Но реплика `c2` была «Продолжи кейс и пиши стратегии», то есть запрет из `c1-5` руководитель снял. Ошибки нет. Ошибочно другое: агент сообщил руководителю, будто нарушил просьбу.
- **Claude Code × `retention-smb`, чат, «Сводка».** Судья Codex засчитал типовую ошибку: срок жизни клиента со страницы «Сводка» приведён как готовое значение. По его же цитате чат пишет, что значение считает формула, то есть получено пересчётом. Не подтверждено.
- **Возможное додуманное содержимое скана договора.** Оба чата Claude Code описали `contract-scan.pdf` и `offer-scan.pdf` как страницу с надписью «Договор, страница 1». Судьи этого проверить не смогли, у человека тоже нет основания считать это выдумкой. В счёт не взято.

## Ограничения

- По одному прогону на ячейку: различия показаны на конкретных задачах, статистической значимости нет.
- Реплики написаны на языке агента: «бриф», «кейс», «пороги». Это перекос в пользу агента. Реплика `c3-2a` сама неудачна и для агента: она предполагает, что агент просил утвердить новое условие (D45, исправлено после сравнения).
- Оба кейса использовались при разработке агента, поэтому агент может быть подогнан под них.
- Слепота неполная. Исполнителя можно угадать по структуре ответа: у агента есть блок «Этап / Готово / Дальше / Жду». Во всех ячейках метки легли одинаково.
- Судьи — модели. Сверка их расхождений человеком не слепая, и правило об округлении принято при сверке, а не записано в протоколе заранее.
- Отрезок сравнения не включает `c4` и `c5`: у чата им нет пары.
- Строка о расходе в `c3-3` этих прогонов была завышена.
