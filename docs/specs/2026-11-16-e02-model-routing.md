# E02. Маршрутизация по модели для модельного собеседника

Карточка [E02](../tasks/IMPROVEMENTS.md#e02-роли-и-маршрутизация). Условия кейса O07, O08. Продолжает [проверяющего E02](2026-11-12-e02-reviewer.md), где маршрутизация между моделями была не-целью, и опирается на [интервью E03](2026-11-09-e03-interviews.md). Статус: включено решением команды 16 ноября 2026 года как исключение из заморозки набора улучшений. Команда выбрала два решения: проверку роли делает утилита по правилам, дешёвая модель задаётся параметром вызова. Остальное решено исполнителем и помечено «моё решение».

## Зачем

Критерий 2 называет маршрутизацию, условие O07 требует «сравнимые прогоны и наблюдаемое восстановление маршрута». Сейчас все роли работают на модели сессии, выбора модели нет нигде.

Модельный собеседник — самая подходящая роль для дешёвой модели: он отвечает двумя–четырьмя предложениями по карточке персонажа, читает только свои правила, а его ответы по определению ничего не подтверждают. Ошибка дешёвой модели здесь стоит один повтор, а не неверный вывод в стратегии.

Успех:

- в журнале прогона видно, что беседа шла на дешёвой модели, и это подтверждается журналом среды, а не только записью агента;
- ответ проверен утилитой; при провале та же беседа повторена на модели сессии, повтор и его причина записаны;
- при чтении беседы с маршрутизацией не хуже бесед без неё;
- расход собеседника измерен и показан как есть.

Провал, даже если всё формально работает:

- в отчёте заявлена экономия, которой не видно в числах, или разница в пределах шума названа выигрышем;
- ответ, отклонённый проверкой и заменённый повтором, попал в источники кейса;
- агент пишет в шапке дешёвую модель, а вызов шёл без параметра;
- проверка роли подаётся как проверка смысла: она ловит форму, подыгрывание вопросу ей недоступно;
- без файла маршрута путь интервью ломается или ведёт себя иначе, чем до изменения.

## Цели, не-цели и границы

Цели:

- утилита `tools/role_check.py`: проверка ответов собеседника по правилам роли, без модели;
- файл маршрута `agent/workflows/interview-routing.md` и ссылка на него из шага 6 [`interviews.md`](../../agent/workflows/interviews.md);
- строки о модели и проверке в шапке беседы, запись модели и повтора в журнале действий;
- строка `routing` в отчёте прогона `scripts/live_report.py`;
- ключ `-NoRouting` в `scripts/live-entry.ps1` для сравнения.

Не-цели:

- дешёвая модель для проверяющего `reviewer` и для любых шагов основного агента;
- оценка смысла ответа моделью-судьёй;
- новая проверка в `gate.py` и в валидаторе: выключенный маршрут не должен ломать путь;
- вызов моделей по API из утилит, ключи, внешние сервисы;
- изменение объявлений роли `.claude/agents/respondent.md` и `.codex/agents/respondent.toml`, правил `agent/roles/respondent.md` и хука;
- обещание экономии.

## Подходы

1. **Модель в параметре вызова — выбран командой.** Объявление роли не меняется. Первая попытка вызывается с дешёвой моделью, повтор без параметра, на модели сессии. В Claude Code и в Codex механизм один, маршрут описан в одном файле, откат и прогон без маршрутизации сводятся к удалению этого файла. Цена: агент может забыть параметр, беседа молча пойдёт на модели сессии; отчёт прогона это показывает.
2. **Модель в объявлении роли.** В Claude Code дешёвая модель гарантирована, но для повтора нужна вторая роль с копией хука, а в Codex объявления через `spawn_agent` не выбираются, и там всё равно нужен параметр. Два механизма вместо одного.
3. **Утилита сама вызывает модели по API.** Нужны ключи и внешний сервис; условия просят папку агента, работающую средствами среды.

Кто проверяет роль: утилита по правилам (выбрано командой) против основного агента. Агент знает гипотезы исследования и судит предвзято, его решение не воспроизводится, а проверка тратит токены модели сессии.

## Решения

### Файл маршрута

`agent/workflows/interview-routing.md` — единственное место, где названы дешёвые модели и порядок повтора. В шаге 6 `interviews.md` добавляется одна фраза: если этот файл есть, беседы идут по нему; если нет, как раньше. Так же устроено выключение проверяющего: нет файла — шаг пропускается молча. Моё решение.

Файл входит в обязательные файлы `scripts/package.py`.

### Какая модель

| Среда | Первая попытка | Повтор |
|---|---|---|
| Claude Code | субагент `respondent`, параметр `model: haiku` у инструмента вызова субагента | тот же вызов без параметра `model` |
| Codex | `spawn_agent` с `fork_turns: "none"` и параметром `model: gpt-6-luna` | тот же вызов без параметра `model` |
| Другая среда с субагентами | параметр модели, если инструмент его принимает | без параметра |
| Среда без субагентов, запасной путь `chat_persona` | маршрута нет: отвечает модель сессии | — |

Название дешёвой модели Codex `gpt-6-luna` взято из каталога `codex debug models` версии 0.167.0-alpha.3.2 (запись — в [`environments.md`](../environments.md#маршрут-модельного-собеседника-e02)); действие параметра `model` у `spawn_agent` подтверждено канарейкой 16 ноября 2026 года.

В Codex ветка «среда показывает субагента `respondent`» параметра модели не имеет, поэтому при включённом маршруте беседа идёт через `spawn_agent`.

Первый шаг реализации, до любых правок, — канарейка в Claude Code: один короткий вызов объявленного субагента `respondent` с параметром `model` под `claude -p --output-format stream-json`. Она отвечает на два вопроса: меняет ли параметр модель субагента и как это записано в журнале. Сохранённый журнал канарейки становится образцом для отчёта прогона: из него берутся точные имена полей с моделью вызова и с расходом по моделям, а не из памяти. Канарейка — платный живой вызов, запускается после согласия команды. Если параметр не действует, работа останавливается и возвращается к команде с вариантом «модель в объявлении роли».

Имя модели сессии агент пишет так, как её называет среда, по правилу из [`checkpoint.md`](../../agent/workflows/checkpoint.md#журнал-действий). Если среда её не называет, ключ `--model` у повтора не передаётся, а в шапке стоит `модель сессии`.

### Ход одной беседы

1. `action start --kind model --tool respondent --model <дешёвая модель> --input-ref <как сейчас>`, вызов субагента с параметром модели.
2. Агент записывает беседу в `sources/interviews/synthetic-<персонаж>-<n>.md` в обычном формате, ответы дословно, и запускает проверку роли. Файл пока не регистрируется как источник.
3. Проверка прошла: `action end --outcome completed`, регистрация источника, как сейчас.
4. Проверка не прошла: файл переносится в `state/interviews/rejected-<персонаж>-<n>.md`, `action end --outcome failed`. Затем `action start` с теми же `kind`, `tool`, `input_ref`, `--model <модель сессии>`, `--retry-of <первое действие>`, `--retry-reason 'role_check: <коды>'` и вызов без параметра модели, с текстом `respondent.md` в задании. Ответ снова записывается и проверяется.
5. Повтор тоже не прошёл: третьей попытки нет. Беседа сохраняется и регистрируется с `Проверка роли: не пройдена (<коды>)` в шапке, действие закрывается `completed`, пользователю об этом говорится одной фразой в итоге бесед. Гипотезы из такой беседы записываются по общим правилам: синтетика и так ничего не подтверждает. Моё решение.

Ответ «Роль не загружена» — сбой загрузки, а не провал проверки роли. Он обрабатывается как сейчас: действие закрывается `failed`, вызов повторяется на той же дешёвой модели с текстом `respondent.md` в задании, с `--retry-of` и причиной «роль не загружена». Проверка роли применяется к ответу этого повтора, и дальше действуют пункты 3–5. Код `ROLE_NOT_LOADED` в утилите — страховка: такой ответ не может быть записан как пройденный.

Беседа из пункта 5 попадает в источники намеренно: это лучший из двух ответов, он помечен, а отдельной попытки ради формы синтетика не стоит. Число таких бесед берётся из шапок, а не из исхода действия.

Отклонённый ответ хранится в `state/`, потому что это служебный ход работы: в источники он не попадает, но при сравнении прогонов его можно прочитать. Моё решение.

Повтор по проверке роли — не новая беседа: файл и номер те же, предел в три беседы и решение `budget` он не задевает. Повтор после правки карточки пользователем идёт как сейчас, новым файлом, и тоже начинается с дешёвой модели.

На запасном пути `chat_persona` и в среде без параметра модели проверка тоже запускается; при провале повтора нет, действует пункт 5.

### Шапка беседы

К нынешним строкам добавляются две:

```text
Модель: claude-haiku-5-5 (маршрут) | <модель сессии> (повтор) | <модель сессии>
Проверка роли: пройдена | не пройдена (TOO_LONG, FOREIGN_NUMBER)
```

Модель пишется так, как её называет среда. Агент пишет дешёвую модель, только если действительно передал параметр. Без файла маршрута строк нет, и валидатор их не требует. Описание шапки в [`contracts/README.md`](../../agent/contracts/README.md) дополняется этими строками и папкой `state/interviews/`.

### Проверка роли

```text
tools/role_check.py check projects/<case-id> sources/interviews/synthetic-skeptic-1.md
```

Утилита читает файл беседы, по строке шапки `Персонаж: <имя>, карточка research/interviews/personas.md` находит раздел этого персонажа в файле карточек и проверяет каждый ответ. Образец формата беседы — [`synthetic-skeptic-1.md`](../../agent/contracts/examples/valid/demo-case/sources/interviews/synthetic-skeptic-1.md) в примерах контракта, требования к карточке — в [методике](../../agent/knowledge/interviews.md#карточка-персонажа). Если раздел персонажа однозначно не находится, числа сверяются со всем файлом карточек. Выход 0 — пройдена; иной код и список нарушений в том же JSON-формате ответа, что у остальных утилит, — не пройдена. Модель не вызывается, в папку кейса утилита ничего не пишет.

| Код | Что ловит | Правило роли |
|---|---|---|
| `ROLE_NOT_LOADED` | в ответе есть «Роль не загружена» | — |
| `ANSWER_MISSING` | у вопроса нет ответа или ответ пуст | — |
| `TOO_LONG` | в ответе больше шести предложений | 7 |
| `FOREIGN_NUMBER` | число цифрами, которого нет ни в карточке, ни в этом вопросе; однозначные целые не считаются | 4 |
| `SPEAKS_FOR_OTHERS` | фраза из короткого списка: «все так считают», «большинству клиентов», «клиентам это нужно» и подобные | 5 |
| `OUT_OF_ROLE` | фраза из короткого списка: «как ИИ», «как языковая модель», «в карточке», «согласно карточке», «советую вам», «рекомендую вам» | 6, 7 |

Порог длины шесть, а не четыре из правил роли: счёт предложений по знакам препинания неточен, а ложный провал стоит лишнего вызова модели сессии. Списки фраз лежат в самой утилите, короткие, сравнение без учёта регистра. Точные списки, разбор предложений и способ найти карточку по шапке — на усмотрение исполнителя; каждый код должен иметь тест с проходящим и непроходящим примером. Моё решение.

Отказ утилиты (нет карточки, шапка не разбирается) — не «пройдена» и не провал роли. Агент один раз исправляет шапку и запускает проверку снова; если отказ остался, беседа регистрируется с `Проверка роли: не проведена (<причина>)`, повтора на модели сессии нет, пользователю говорится одной фразой.

Строка `Модель` в шапке одна: значения через `|` выше — варианты.

Чего проверка не видит: подыгрывание вопросу, выдуманные обстоятельства без чисел, ответ не по карточке. Это пишется в файле маршрута и в отчёте: проверка роли — проверка формы.

### Отчёт прогона

`scripts/live_report.py` добавляет строку:

```text
routing talks=3 cheap=3 retried=1 failed_twice=0 called_with_model=3 cost_by_model={...}
```

- `talks` — файлы бесед в `sources/interviews/`, не пришедшие из архива переноса;
- `cheap` — файлы в `sources/interviews/` и `state/interviews/` с пометкой `(маршрут)` в строке `Модель`: столько первых попыток агент объявил дешёвыми. Имя модели не сравнивается, поэтому неизвестное имя модели сессии счёт не портит;
- `retried` — действия журнала кейса с `retry_reason`, начинающимся с `role_check`;
- `failed_twice` — шапки с `Проверка роли: не пройдена` только в `sources/interviews/`: отклонённый файл в `state/interviews/` несёт ту же строку с причиной, но считается в `retried`;
- `called_with_model` — из журнала среды: в Claude Code число вызовов субагента `respondent`, у которых в аргументах есть модель; в Codex — число вызовов `spawn_agent` с непустым `model` и `task_name` с `respondent` в файлах сессий родителя под `codex_home`, без `codex_home` при журналах Codex `unknown`;
- `cost_by_model` — из итогового события Claude Code с расходом по моделям, если оно есть; в Codex `unknown`.

Имена полей журнала среды берутся из образца канарейки. Отклонённый файл в `state/interviews/` сохраняет свою шапку.

`cheap` больше `called_with_model` значит, что агент записал дешёвую модель без вызова с параметром: это провал прогона, строка помечается.

### Выключатель для сравнения

`scripts/live-entry.ps1 -NoRouting` удаляет из клона `agent/workflows/interview-routing.md`, проверяет, что его нет, и пишет в `checks.txt` строку `routing off`; без ключа — `routing on`, и скрипт падает, если файла в клоне нет. Ключ принимает только набор `interviews`. Рабочая папка получает суффикс `-norouting`. `-PlainChat` с ключом не связан: он допустим только в наборе `hard`, где интервью нет. Сухой прогон в CI идёт и с этим ключом. Устройство повторяет `-NoReviewer`.

## Проверки

Офлайн:

- `tests/test_role_check.py`: каждый код на проходящем и непроходящем примере; беседа из образцового прогона проходит; число из карточки и из вопроса не считается чужим; испорченный файл и отсутствующая карточка дают отказ, а не «пройдена»;
- `tests/test_live_report.py`: строка `routing` при маршруте, при повторе, при записи модели без вызова с параметром, без файла маршрута;
- упаковка: файл маршрута и утилита входят в обязательные файлы;
- сухой прогон `interviews` с `-NoRouting` в CI;
- оба обязательных скрипта и весь набор тестов.

Живые, после согласия команды на бюджет: канарейка параметра модели в Claude Code, затем набор `interviews` в четырёх ячейках — Claude Code и Codex, с маршрутом и с `-NoRouting`, один прогон на ячейку.

Что сравнивается:

1. Маршрут наблюдался: `called_with_model` не меньше `cheap` и больше нуля. Равенства не требуется: повтор после «Роль не загружена» даёт второй вызов с моделью при одном файле беседы.
2. Восстановление: сколько бесед повторено и по каким кодам; отклонённые ответы прочитаны, провал настоящий или ложный.
3. Качество: беседы обоих вариантов прочитаны целиком. Отмечается выход из роли, чужие сведения, советы, речь за других, пропущенные проверкой.
4. Расход и время набора; в Claude Code — расход по моделям, отдельно расход дешёвой модели, то есть первых попыток собеседника.

## Решение об откате

Оставляем, если хотя бы в одной среде маршрут наблюдался, повтор отработал или не понадобился, и при чтении беседы не хуже варианта без маршрута.

Откатываем, если маршрут не наблюдался ни в одной среде; если повторена половина бесед или больше, то есть дешёвая модель роль не держит; если при чтении беседы заметно хуже. Откат — удаление файла маршрута, утилиты, строки отчёта и ключа одним PR; карточка E02 сохраняет запись о попытке и результате.

Полный расход набора в решении не участвует, это моё решение. Собеседник — малая доля набора: на канарейке вызов дешёвой модели стоил 0,0011 USD из 0,104 USD, а полный прогон стоит доллары. Разброс полного расхода между прогонами одной ячейки больше всей возможной разницы на собеседнике (у `hard` оценка расхода — от 3,33 до 16,70 USD), а прогон в ячейке один, так что сравнение двух сумм решало бы случай. Расход собеседника из обоих вариантов тоже не сравнить: без маршрута его вызовы считаются вместе с моделью сессии. Расходный провал маршрута ловит условие о повторах: с ним собеседник стоит `N·дешёвая + r·сессия` против `N·сессия` без него, где `N` — беседы, `r` — повторы. Дороже это только при доле повторов выше `1 − дешёвая/сессия`, а пока дешёвая модель стоит не больше половины модели сессии, этот порог не ниже половины бесед, на которой уже откатываем.

Отчёт записывает полный расход и время обоих вариантов как есть. Разброс при одном прогоне на ячейку неизвестен, поэтому разница выводом не сопровождается: ни «экономия», ни «рост расхода».

- **Агент забывает параметр.** Беседа идёт на модели сессии, результат не страдает. Видно по `called_with_model`.
- **Параметр не действует на объявленного субагента в Claude Code.** Проверяется канарейкой до правок; если не действует, возвращаемся к команде с вариантом «модель в объявлении роли».
- **Codex.** Вызов субагента в `codex exec --json` не виден, он читается по файлам сессий. Без `codex_home` в Codex `called_with_model` равен `unknown` и маршрут не доказан, это пишется как ограничение.

- **Срок.** 17–18 ноября расширение функций останавливается. Живые прогоны — четыре платных набора; если бюджета или времени нет, изменение не сливается с заявлением о пользе.
