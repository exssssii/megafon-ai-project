# B10. Проверяемые вычисления

Спецификация задачи B10 из [карточек](../tasks/CORE.md), уточняет разделы 4 и 5 [ТЗ](2026-11-04-product-agent-tz.md), опирается на [контракты B01](2026-11-05-b01-contracts.md), [чтение материалов B04](2026-11-05-b04-read-materials.md), [утверждения B05](2026-11-05-b05-evidence.md) и контрольные числа [B03](2026-11-05-b03-acceptance.md). Статус: решения по задаче приняты исполнителем; спецификация проходит проверку в PR.

## Зачем

Запись `CALC` есть с B01, но число в ней держится на честном слове. Валидатор проверяет только, что ссылки и локатор существуют: значение входа, формула и результат ничем не сверяются. Модель может вписать 1540 вместо 1440, и кейс останется зелёным. Во входе из CSV нельзя указать столбец, у локатора `rows` есть только строки. Из-за этого «отток 6,27%» в стратегии нельзя отличить от выдуманного.

Успех: агент описывает расчёт одним запросом, значения входов утилита берёт из извлечённого текста сама, формулу считает ограниченный вычислитель, а валидатор пересчитывает каждую такую запись. Пропуск, текст вместо числа, сложение тысяч с рублями, деление на ноль и разные периоды в отношении не превращаются в точное число молча.

Провал даже при зелёных тестах: числитель и знаменатель посчитаны на разных строках после «пропуска» пустой ячейки; квартальный отток сравнивается с месячным как одно и то же; средняя месячная доля выдана за отношение сумм; неполная неделя вошла в итог как полная; утилита исполнила выражение из материала.

## Границы

Входит:

1. Модуль `tools/calc_engine.py`: разбор чисел, получение значения входа из блоков, разбор и вычисление формулы с учётом единиц и периодов, округление. Общий для утилиты и валидатора, как `evidence_blocks.py`, чтобы оба отвечали одинаково.
2. Утилита `tools/calc.py`: `add` (записать расчёт), `check` (пересчитать записи, только чтение).
3. Отзыв расчёта командой `tools/evidence.py withdraw`: она уже понижает зависимые утверждения для источников и утверждений, B10 добавляет `CALC`.
4. Проверка в `tools/validate_project.py`: пересчёт записей с формулой, новые коды `CALC_MISMATCH` и `CALC_UNVERIFIED`.
5. Расширение схемы `registry-calculations` необязательными полями, обновление `agent/contracts/README.md`, раздела кодов в спецификации B01, образца `examples/valid/demo-case` и примеров `examples/invalid/`.
6. Процедура `agent/workflows/calculations.md`, методика `agent/knowledge/calculations.md`, ссылка из `agent/instructions/product-mode.md`.
7. `trace` показывает формулу, свёртку и столбец входа.

Не входит: группировка и сводные таблицы, статистические методы и доверительные интервалы, прогнозы и регрессии (это E07), пересчёт формул XLSX, чтение чисел из сайтов без сохранённого текста, выбор вопросов исследования (B08), журнал действий (B13). Агент по-прежнему решает, что считать: утилита отвечает за то, что посчитанное следует из данных.

## Команды

Вызов как у B04 и B05: `.venv/Scripts/python.exe tools/calc.py <команда> …`, вне Windows `.venv/bin/python`. Сеть не нужна.

| Команда | Что делает | Пишет в кейс |
|---|---|---|
| `add <кейс> <запрос>` | Берёт значения входов из блоков, вычисляет формулу, записывает `CALC` | `evidence/calculations.json` |
| `check <кейс> [CALC-NNNN]` | Пересчитывает одну или все активные записи с формулой | нет |

Коды выхода `add`: 0 записано, 4 ничего не записано (отказ), 5 сбой. Коды `check`: 0 расхождений нет, 1 найдено расхождение, 4 отказ, 5 сбой. Первая строка вывода — JSON без текста материалов: только числа, ID, имена входов и коды. Отзыв — `tools/evidence.py withdraw <кейс> CALC-NNNN --reason '…'`.

`reproduce` записи, сделанной утилитой, — команда `tools/calc.py check projects/<case-id> CALC-NNNN`.

### Запрос файлом

Как в B05: JSON в UTF-8 в `projects/<case-id>/sources/incoming/<имя>.json`, утилита удаляет его после записи. Имя столбца CSV и цитата приходят из материала, поэтому в оболочку не попадают.

```json
{
  "description": "Месячный отток мастеров-одиночек до смены тарифа",
  "inputs": [
    {"name": "ушедшие", "source_id": "SRC-0002", "block": 2, "block_to": 10, "column": "E",
     "aggregate": "sum", "unit": "клиентов", "period": "2025-04..2025-12"},
    {"name": "база", "source_id": "SRC-0002", "block": 2, "block_to": 10, "column": "C",
     "aggregate": "sum", "unit": "клиентов", "period": "2025-04..2025-12"}
  ],
  "formula": "100 * ушедшие / база",
  "result": {"unit": "%", "period": "2025-04..2025-12", "digits": 2},
  "assumptions": ["Отток месяца — ушедшие к активным на начало месяца"],
  "gaps": []
}
```

Обязательны `description`, `inputs`, `result` с ключами `unit` и `period` (значение может быть `null`, если оно неизвестно), и либо `formula`, либо `not_computable`. Необязательны `assumptions`, `gaps`, `period_mix`, `result.digits`.

### Входы

Имя входа — идентификатор из букв (в том числе кириллицы), цифр и `_`, не с цифры и не служебное слово Python. Имена в запросе уникальны. Каждый вход должен встретиться в формуле: неиспользованный вход вводил бы читателя в заблуждение.

| Вид | Поля запроса | Значение |
|---|---|---|
| Таблица XLSX | `source_id`, `block`, `block_to`, `column` (буква), `aggregate` | Ячейки столбца в строках блоков с `block` по `block_to` одного листа |
| Таблица CSV | `source_id`, `block`, `block_to`, `column` (номер с 1 либо точный заголовок из первой строки), `aggregate` | Ячейки столбца в строках с `block` по `block_to` |
| Текст MD, TXT, DOCX, PDF, страница сайта | `source_id`, `block`, `quote` | Единственное число в дословной цитате блока |
| Другой расчёт | `calculation_id` | Результат активного рассчитанного `CALC` вместе с его единицей и периодом |

У входов из источников обязательны `unit` и `period` (строка либо `null`). У входа-расчёта их не указывают: они копируются из результата.

Таблица:

- `block_to` по умолчанию равен `block`. `aggregate`: `value` (ровно одна ячейка), `sum`, `mean`, `min`, `max`, `count`. При одной строке по умолчанию `value`, при нескольких поле обязательно.
- Строки берутся подряд по номерам строк файла, а не по номерам блоков. Строка XLSX без единого значения не даёт блока, значит её ячейка пуста.
- Пустая ячейка, формула без сохранённого значения, текст, логическое значение, дата — отказ с адресами ячеек. Пропуск не выбрасывается молча: агент разбивает диапазон на части вокруг пропуска и называет пробел. Так числитель и знаменатель гарантированно считаются на одних строках.
- Число в ячейке XLSX берётся как есть. Строка CSV или текстовая ячейка разбирается по правилам ниже.
- Ячейки с формулой и сохранённым значением допустимы, ответ называет их в `warnings`: свежесть значения не проверена.
- Заголовок CSV ищется в первой строке файла и должен встретиться ровно один раз. В записи хранится номер столбца.

Текст:

- Цитата сверяется так же, как в B05 (`quote_in`): дословно, с точностью до пробелов, число не может оказаться частью более длинного. Локатор берётся из блока: абзац, страница или строка таблицы документа, никогда не `section`, поэтому блок для пересчёта однозначен.
- В цитате должно быть ровно одно число. Иначе отказ: агент сокращает цитату. Тире (U+2013) прямо перед числом, которое не стоит после другого числа, — отказ `ambiguous_sign`: в русских текстах так пишут минус, и молча прочитать «–5%» как 5 нельзя. Тире между двумя числами — диапазон, это просто два числа. Масштаб словами («6,6 млн») не применяется: значение 6,6, единица «млн субъектов» на совести агента и видна в записи.

Разбор числа (общий для CSV, текстовых ячеек и цитат): необязательный знак (`-`, `+`, `−`), цифры с группами по три через пробел или неразрывный пробел, необязательная дробная часть через `,` либо `.`, необязательный `%` в конце (знак отбрасывается, единицу агент указывает сам). Одновременно `.` и `,` — отказ: неясно, что из них разделитель разрядов. `1,234` читается как 1,234: в русских материалах запятая — десятичный разделитель. Правило записано в процедуре.

Источник входа должен быть активным, разрешённым и прочитанным, как опора утверждения. Источник со статусом `partial` допустим, ответ называет его в `warnings` (`SOURCE_PARTIAL`).

### Формула

Арифметика над именами входов и числами: `+`, `-`, `*`, `/`, унарный минус, скобки. Других функций, атрибутов, вызовов, степеней, сравнений и строк нет: разбор идёт по дереву выражения с перечнем разрешённых узлов, не через `eval`. Длина формулы до 500 символов.

Арифметика и свёртки идут в десятичных числах с 60 значащими цифрами, а не в `float`: доли, которые в сумме дают целое, оставляют ровно ноль, и «остаток после двух долей» не превращается в деление на 5e-17. Значение по модулю больше 1e300 — отказ `overflow`, а не сбой.

Деление на ноль не ошибка запроса: запись создаётся со статусом `not_computable`, в `gaps` утилита добавляет, какой знаменатель равен нулю. Это честный результат для «доли попробовавших при нуле показов» и «маржи на оплату без оплат». Бесконечность и переполнение — отказ.

### Единицы и периоды

Утилита ведёт размерность выражения. Единица входа — непрозрачная метка: строка без учёта регистра и повторных пробелов, `null` — неизвестная единица. Составные метки вроде `руб./клиент` не разбираются. Умножение и деление складывают и вычитают степени меток, одинаковые сокращаются: `клиентов / клиентов` безразмерно. Число безразмерно. Размерность действует внутри одной формулы. Следующий расчёт видит уже единицу, которую агент записал у результата. Поэтому `клиенты * тариф` по трём сегментам складываются в одной формуле, а сумму произведения с готовыми рублями из другого места агент делает отдельным расчётом, назвав единицу результата.

Период входа сравнивается как строка без учёта регистра и повторных пробелов. Неизвестный период (`null`) нейтрален, как число: он не создаёт смешения и не снимает его. Части одного периода, разбитого вокруг пропуска, агент подписывает одинаково, например `2026-01..2026-09 без 2026-02 и 2026-03`, и складывает их без объяснения. Подвыражение несёт множество периодов своих входов. Период результата утилита не выводит: его пишет агент.

- `+` и `-` требуют одинаковой размерности у слагаемых. Число допускается рядом с любой размерностью (`1 - доля`). Иначе отказ `unit_mismatch`. Перевод тысяч в рубли — отдельный расчёт: `выручка * 1000` с единицей результата `руб.` и допущением о переводе. Следующий расчёт берёт его результат уже в рублях.
- `+`, `-` и `/` над подвыражениями с известными и разными множествами периодов — отказ `period_mix`, пока запрос не содержит поле `period_mix` с объяснением, почему смешение верно. Объяснение попадает в `assumptions` записи с пометкой «Разные периоды:». `period_mix` без смешения — отказ: допущение не должно описывать то, чего нет. Законные случаи — квартальный отток к базе на начало квартала и вывод пропуска из баланса («начало апреля − новые марта + ушедшие марта»). Ошибка, которую ловит правило, — оплаты за 8 недель к активным за 11.
- `*` разных периодов допускает без объяснения: клиенты месяца на тариф — обычная запись.
- Единица результата не сверяется с размерностью: `100 * доля` с единицей `%` законна. Ответ показывает вычисленную размерность (`dimension`), агент сверяет её сам.

### Результат и запись

Значение округляется до `result.digits` знаков (0–10, по умолчанию 6) половиной вверх через десятичное представление. Целое значение хранится целым числом. Расчёты-потребители берут уже записанное значение, поэтому цепочка воспроизводится побайтно.

Запись:

```json
{
  "id": "CALC-0003", "created_at": "…", "record_status": "active",
  "inputs": [
    {"name": "ушедшие", "source_id": "SRC-0002", "locator": {"kind": "cells", "sheet": "Сегменты", "range": "E2:E10"},
     "aggregate": "sum", "value": 300, "unit": "клиентов", "period": "2025-04..2025-12"},
    {"name": "оплаты", "source_id": "SRC-0003", "locator": {"kind": "rows", "from": 26, "to": 36}, "column": 6,
     "aggregate": "sum", "value": 3420, "unit": "оплат", "period": "недели 1–11"}
  ],
  "method": {"kind": "tool", "description": "…", "formula": "100 * ушедшие / база", "digits": 2},
  "result": {"status": "computed", "value": 3.34, "unit": "%", "period": "2025-04..2025-12"},
  "gaps": [], "assumptions": ["…"],
  "reproduce": "tools/calc.py check projects/retention-smb CALC-0003"
}
```

Новые необязательные поля схемы: у входа-источника `column` (буква столбца для XLSX не нужна, она в диапазоне; номер с 1 для CSV) и `aggregate`; у `method` — `formula` и `digits`. Вход-цитата хранит локатор блока с `quote`. Старые записи остаются валидными, поэтому `format_version` остаётся 1: по правилам B01 версию увеличивает только несовместимое изменение.

`not_computable` по запросу: `"not_computable": true` без `formula`, с непустым `gaps`. Так записывается показатель, для которого нет данных («доля оттока по причинам»). Входы допустимы, если агент хочет показать, что именно было.

При отказе файл запроса остаётся на месте для исправления, как в B05. Повторный `add` того же запроса — те же входы, формула, результат, единица, период — возвращает существующий ID с `existing: true`: повтор после сбоя не плодит записи. Расчёты не изменяются: исправление — отзыв и новая запись, чтобы зависящие от старого значения утверждения и тексты стали видны.

После записи утилита запускает валидатор и при новой ошибке на этой записи восстанавливает реестр, как `evidence.py`.

Ответ `add`: `id`, `existing`, `result`, значения входов с числом ячеек, `dimension`, `warnings` (`SOURCE_PARTIAL`, `formula_cached` с адресами), `case_errors` вне этой записи.

## Проверка в валидаторе

Для каждого активного `CALC` с `method.formula` валидатор заново получает значения входов из извлечённого текста (свёртку ячеек либо единственное число цитаты), значения входов-расчётов из их результатов, сравнивает их с записанными `value`, вычисляет формулу и округляет. Расхождение значения входа, единицы или периода входа-расчёта, результата или статуса — ошибка `CALC_MISMATCH`. Пересчёт не выполняется, если у записи уже есть ошибка ссылки, локатора, цитаты или отзыва: сначала исправляется она, повторять её другим кодом незачем.

Активный `CALC` со статусом `computed` без `method.formula` — предупреждение `CALC_UNVERIFIED`: число записано руками, пересчитать его нельзя. Это не ошибка: старые кейсы и редкий ручной расчёт остаются допустимы, но видны. Тот же код получает запись с формулой, у входа которой нет извлечённого текста: формула и результат проверяются по записанным значениям входов, а сами значения сверить не с чем. `check` относит такие записи к `unverified`, не к `ok`.

Пересчёт не может уронить валидатор: любой сбой пересчёта испорченной записи становится `CALC_MISMATCH`. Длинный диапазон без строк в материале отказывает сразу, не проходя все номера строк, и называет не больше 20 адресов. У входа XLSX поле `column`, если есть, должно совпадать с буквой диапазона.

Валидатор не повторяет проверки единиц и периодов: это охрана при записи, а объяснение `period_mix` уже в допущениях. Подменённые руками единицы входа-источника он не видит; это остаётся задачей ревью и описано ниже.

## Отзыв и навигация

`tools/evidence.py withdraw` принимает `CALC-NNNN`. Запись получает `record_status: withdrawn` и `status_reason`. Утверждения, которые опираются на этот расчёт напрямую или через другие расчёты, понижаются до `unconfirmed` с пометкой в `limits`, как при отзыве источника. Расчёты, вопросы, варианты, решения и тексты `outputs/` только называются. Активная ссылка на отозванный расчёт остаётся ошибкой `WITHDRAWN_USED`.

`trace` для входа выводит `aggregate` и `column`, для записи — `method` целиком, включая формулу.

## Документы агента

Процедура: когда считать утилитой, как выбрать блоки и столбец после `show`, как разбить диапазон вокруг пропуска, как перевести единицы отдельным расчётом, что делать с `period_mix`, `not_computable` и отказами, как сослаться на расчёт в утверждении и стратегии.

Методика, общая, без чисел конкретного кейса:

- сравнивать показатели на одной базе и за один период; иначе называть различие;
- доля за период — отношение сумм, а не среднее месячных долей;
- неполный период не складывается с полными и не экстраполируется молча;
- пропуск можно вывести из баланса (начало + новые − ушедшие = конец) только с явным допущением, иначе это пробел;
- округлять при изложении, не в промежуточных расчётах;
- `not_computable` и условная оценка — законный результат; точное число без данных — нет;
- корреляция и совпадение по времени не доказывают причину;
- невыполнимое требование показывается расчётом разрыва, а не словами.

## Что нельзя проверить автоматически

- Правильно ли выбраны строки: утилита гарантирует, что посчитаны именно они, но не что это нужный сегмент и месяцы. Проверяет агент по `show` и ревью по `trace`.
- Верны ли единица и период, которые агент написал у входа-источника. Утилита не читает их из заголовка: заголовки бывают любыми.
- Осмысленна ли формула: отношение сумм против среднего долей, верная ли база. Это методика и приёмка B08, B11.

## Приёмка и проверки

- Все контрольные числа обоих кейсов B03 из `docs/acceptance/control/*.json` (`numbers`, `derivable`, `required_new_clients`) получаются через `tools/calc.py add` на материалах, зарегистрированных `read_material.py`, в пределах допуска. Исключены `historic_max_new_clients` и `best_month_margin_rub`: это максимум по группам (месяцам, неделям) от сумм нескольких столбцов, а группировки и отбора по условию в B10 нет. Агент может посчитать отдельные месяцы или недели и выбрать наибольшее сам, утилита проверит арифметику каждого, но не выбор. Для невыполнимого требования хватает и оценки сверху: сумма максимумов по сегментам не меньше максимума по месяцам.
- Три показателя `not_computable` из контрольных файлов дают отказ от числа: нулевая база и отсутствие оплат — через деление на ноль, причины ухода — через запрос без формулы.
- Отказы: пустая ячейка, формула без значения, текст и заголовок в диапазоне, сложение разных единиц, деление разных периодов без `period_mix`, цитата с двумя числами, цитата не из блока, отозванный или запрещённый источник, неизвестный или неиспользованный вход, запрещённые конструкции формулы (вызов, атрибут, степень, сравнение, строка, имя функции из материала).
- `CALC_MISMATCH` после ручной правки значения входа, результата, формулы, единицы входа-расчёта; отсутствие ложного `CALC_MISMATCH` при уже найденной ошибке ссылки или локатора. `CALC_UNVERIFIED` на ручном расчёте. Оба кода в спецификации B01 и в `examples/invalid/`.
- Цепочка расчётов, отзыв расчёта с понижением утверждения, повтор `add`, откат при ошибке валидатора, `check` с кодами выхода.
- Вывод утилиты не содержит текста материалов.
- Существующие тесты проходят; ожидания, изменившиеся из-за новых кодов, обновлены с объяснением в PR.
- Обязательные проверки: `scripts/check.ps1`, `scripts/test-checks.ps1`, офлайн-тесты. Живой прогон агента — в B09.

## Что решает исполнитель

Внутреннее устройство модулей, тексты отказов, порядок полей ответа, имена тестов.

## Наши решения, требующие внимания при согласовании

1. Контракт `CALC` расширен необязательными полями без смены версии. Это касается всех, кто пишет расчёты: B07 (PR №9) расчётов не создаёт, B08 будет их использовать.
2. Пропуск в диапазоне — отказ, а не тихое исключение: агенту приходится разбивать диапазон. Это дороже по шагам, зато числитель и знаменатель не расходятся.
3. Разные периоды в `+`, `-`, `/` требуют объяснения, в `*` — нет. Единица результата не сверяется.
4. Ручной расчёт — предупреждение, а не ошибка.
5. Запятая читается как десятичный разделитель.
6. Расчёты неизменяемы, исправление — отзыв и новая запись.
7. Демонстрационный `CALC-0001` образца переписан как запись утилиты, чтобы образец показывал проверяемый путь и не давал предупреждения.
