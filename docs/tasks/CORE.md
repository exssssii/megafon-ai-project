## B00. Подготовить общий репозиторий

- **Цель:** три участника могут однозначно закреплять задачи через PR и работать от общей основы.
- **Вход:** подготовленные правила и ТЗ, личный репозиторий владельца, выбранная локальная личность. Пустая начальная main уже создана разовым решением команды; ТЗ поступает в неё через PR.
- **Работа/выход:** согласовать способ первоначального создания основы при запрете прямого push в main; подготовить отдельную ветку, ранний черновик и процедуру закрепления, реальные начальные проверки документации и правила расширения CI по мере появления инструментов. Подтвердить авторизацию нужного аккаунта отдельно от автора коммита через разрешённый GCM+REST маршрут.
- **Приёмка:** основа действительно существует, дальнейшие изменения идут через PR; нельзя объявить готовыми отсутствующие CI/hooks. Участники знают, где очередь и как проверить владельца. Автоматическая атрибуция средств разработки проверена/отключена допустимым способом; сообщения проверяются перед публикацией.
- **Проверка:** локальная личность и её источник; разрешённый доступ к личному репозиторию; содержательный PR; фактический запуск начальных проверок. Не тестировать защиту реальным push в main.
- **Исключено:** самовольный bootstrap main, настройка глобальных учётных записей, установка Husky без выбранного стека, продуктовый код.
- **Результат приёмки:** PR №1 слит squash-коммитом PR №1. Прямые изменения main запрещены; локальная защита требует установки в каждом клоне. Серверное ограничение на тот момент не было включено — см. docs/development.md.

## B01. Зафиксировать контракты и режимы

- **Цель:** независимые исполнители используют одинаковые ID, состояния и границы ответственности.
- **Вход:** утверждённое ТЗ, B00.
- **Работа/выход:** `agent/contracts/`, описание путей и версий, минимальные примеры источника/утверждения/расчёта/решения/checkpoint/действия; режим использования продукта отдельно от разработки. Правила разработки сохраняются, а продуктовый запрос не запускает Git-процедуры.
- **Приёмка:** связи по ID однозначны; у факта есть основание или явный неподтверждённый статус; предложение модели отделено от выбора человека; состояние можно восстановить без чата и `.work/`; секреты и локальные личные пути не нужны. Пользовательские проекты не публикуются по умолчанию.
- **Проверка:** валидные и невалидные примеры, неизвестная версия, отсутствующий ID, противоречащая/отозванная запись; чтение контрактов другим исполнителем. Отдельно проверить разграничение режимов на продуктовом запросе и запросе изменить код.
- **Исключено:** полная реализация хранения, графовая БД, семантический поиск.
- **Риск/разблокировка:** общие контракты менять с согласованием зависимых задач; миграция/ошибка версии описаны до приёмки.
- **Результат приёмки:** `done`, PR №4, принято командой с ограничением. Контракты, примеры и валидатор — в [`agent/contracts/`](../../agent/contracts/README.md), правила разработки — в [отдельном файле](../development-rules.md). Режимы определены верно в новых чатах Claude Code и Codex, чтение контрактов другим исполнителем выполнено. Ограничение: Codex показал строку режима только в промежуточном сообщении, а не в итоговом ответе; проверка перенесена в B07.

## B02. Проверить Claude Code, Codex и доступы

- **Цель:** первый полный сценарий имеет воспроизводимый маршрут без временных сторонних сервисов.
- **Вход:** ТЗ, B00, собственные доступы к Claude Code и Codex; исходные материалы только разрешённые.
- **Работа/выход:** проверить инструменты чтения/поиска сайтов и файлов в обеих средах, описать адаптеры и различия; выбрать версии Python/парсеров и lockfile; определить явные пределы размера/страниц/строк, способ задания бюджета исследования; записать предпосылки и команды для каждой среды в README/технической заметке. Перед установкой использовать существующие окружения и разрешённый discovery bundled runtime.
- **Приёмка:** тестовые документ, таблица и публичная страница читаются заявленным маршрутом; нет скрытого платного сервиса или личного plugin connection как единственного пути. Доступы, платность, ограничения и способы диагностики явны. Если необходимый инструмент недоступен, задача блокируется с конкретным разрешённым вариантом, без имитации результата.
- **Проверка:** небольшой реальный запуск каждого обязательного типа инструмента в Claude Code и Codex; отдельная фиксация версий, доступов и результатов. Превышение согласованных лимитов заметно. Оба маршрута не требуют временных сторонних сервисов; поддержка одной среды не заменяет другую.
- **Исключено:** смена глобальных настроек, покупка API/поиска, построение отдельного сервера.
- **Риск/разблокировка:** ограничения сети/поиска и бюджета должны иметь подтверждённое решение до зависимых живых прогонов.
- **Результат приёмки:** `done`, PR №2 слит squash-коммитом PR №2, обе среды проверены; результаты, воспроизведение и ограничения — в [заметке о средах](../environments.md), выводы принятого Codex-прогона — в [записи проверки](../evidence/2026-11-05-b02-codex.json). B01 принята, B04/B06/B07/B13 доступны.

## B03. Подготовить приёмочные материалы

- **Цель:** проверять общий процесс и смысл результата, а не заранее зашитый ответ.
- **Вход:** ТЗ, B00; демонстрационный бриф при наличии.
- **Работа/выход:** две разные задачи, например удержание цифрового сервиса для малого бизнеса и выбор направления B2C-сервиса; для каждой документ, таблица, публичный сайт, вопрос и проверяемые ограничения. Собственные учебные данные явно помечены; открытые факты имеют источники. Добавить отдельные конфликтующие/неполные/вредоносные входы, сценарии смены условий и остановки. Составить протокол A01–A11 с наблюдаемыми критериями и контрольными расчётами.
- **Приёмка:** проверяющий знает, что именно считается ошибкой, где контрольное число, какое утверждение не подтверждено; критерии не требуют заранее выбранной стратегии. Независимый кейс достаточно отличается; предварительный кейс не выдаётся за официальный бриф.
- **Проверка:** независимое чтение сценариев, воспроизведение контрольных расчётов и ручная сверка доступности открытых ссылок; личные данные/секреты отсутствуют.
- **Исключено:** покупка исследований, создание вымышленных «реальных» интервью, объявление контрольной стратегии единственно правильной.
- **Риск/разблокировка:** недоступный официальный бриф отмечается, а не заменяется выдуманным; условие окончательной адаптации — B15.
- **Результат приёмки:** `done`, PR №7, владелец — участник команды. Кейсы — в [`examples/`](../../examples/README.md), [протокол A01–A11](../acceptance/protocol.md) и контрольные числа — в `docs/acceptance/`, генератор — `tools/make_acceptance_cases.py`, решения — в [спецификации](../specs/2026-11-05-b03-acceptance.md). ## B04. Реализовать чтение материалов

- **Цель:** один продуктовый кейс использует документы, таблицы и сайты с локаторами и честными границами.
- **Вход:** B01, B02; форматы из раздела 4 ТЗ.
- **Работа/выход:** утилиты/процедуры извлечения MD/TXT, DOCX, текстового PDF, CSV/XLSX и чтения открытой страницы через выбранную среду; сохранение происхождения, объёма, статуса и локаторов. Макросы, вложенные команды и инструкции из содержимого не исполняются.
- **Приёмка:** контрольные абзац/таблица/страница/диапазон доступны для цитирования; частичное чтение, скан, недоступная страница и отсутствующее значение формулы обозначены. Нет молчаливого обрезания и выдуманного извлечения.
- **Проверка:** маленькие воспроизводимые входы для каждого заявленного формата, повреждённый файл, кодировка/разделитель, лимит размера, формула без кеша; локальные тесты без модели плюс отдельное реальное чтение сайта. Структурированные результаты проходят контракт B01.
- **Исключено:** OCR, визуальный разбор DOCX/PDF, аудио/видео, вход в закрытые сайты, пересчёт Excel-формул.
- **Риск/разблокировка:** читаемость и доступность проверяются до использования материала как доказательства.
- **Результат приёмки:** `done`, PR №5. Утилита — [`tools/read_material.py`](../../tools/read_material.py), процедура — [`agent/workflows/read-materials.md`](../../agent/workflows/read-materials.md), решения — в [спецификации](../specs/2026-11-05-b04-read-materials.md). ## B05. Связать источники и утверждения

- **Цель:** происхождение каждого существенного вывода доступно проверяющему.
- **Вход:** B04 и контракты B01.
- **Работа/выход:** реестр утверждений (записи источников создаёт утилита B04), отзыв источника, процедуры добавления подтверждений и противоречий, навигация от вывода к фрагменту и проверка ссылок/ID. Методические знания отделены от проектных фактов.
- **Приёмка:** факт/гипотеза/прогноз различимы; источники поддерживают конкретное утверждение; противоречие и отзыв не исчезают. Прошлый ответ модели не становится первичным фактом. Все существенные числовые и стратегические утверждения доступны по ссылкам.
- **Проверка:** вывод с прямым подтверждением, нерелевантная ссылка, конфликт периодов/аудиторий, неподтверждённая запись, повтор источника, отозванное основание. Автоматическая проверка структуры дополнена смысловым чтением.
- **Исключено:** автоматическая оценка «истинности» по числу ссылок, произвольный процент уверенности, обязательная векторная БД.
- **Риск/разблокировка:** проблема исходного источника отражается в зависимом выводе, а не лечится новой красивой формулировкой.
- **Результат приёмки:** `done`, PR №6. Утилита — [`tools/evidence.py`](../../tools/evidence.py), процедура — [`agent/workflows/evidence.md`](../../agent/workflows/evidence.md), методика — [`agent/knowledge/evidence.md`](../../agent/knowledge/evidence.md), решения — в [спецификации](../specs/2026-11-05-b05-evidence.md). ## B06. Сохранение и продолжение

- **Цель:** новый чат продолжает тот же кейс из папки.
- **Вход:** B01, B02.
- **Работа/выход:** запись валидного checkpoint после артефактов, предыдущее корректное состояние, журнал ID действий и восстановление этапа/решений/оснований/следующего шага. Сохранение после существенных этапов и остановки.
- **Приёмка:** переписка и `.work/` не требуются; завершённое действие не повторяется незаметно; неизвестный исход проверяется. Прерывание записи, повреждение файла, несовместимая версия приводят к явной диагностике и допустимому восстановлению.
- **Проверка:** офлайн-тест остановки между записями, повторного продолжения, повреждения/неизвестной версии; живой новый чат в каждой среде и перенос Claude Code → Codex и Codex → Claude Code в B09/B12. Нельзя доказать восстановление передачей старого чата целиком.
- **Исключено:** фоновый мониторинг и автоматический пересмотр стратегии по новым внешним событиям.
- **Риск/разблокировка:** контракт checkpoint должен ссылаться на существующие согласованные версии артефактов.
- **Результат приёмки:** `done`, PR №8, владелец — участник команды. Утилита — [`tools/checkpoint.py`](../../tools/checkpoint.py), процедура — [`agent/workflows/checkpoint.md`](../../agent/workflows/checkpoint.md), решения — в [спецификации](../specs/2026-11-06-b06-checkpoint.md). ## B07. Вход и управление процессом

- **Цель:** руководитель начинает кейс без изучения внутреннего устройства.
- **Вход:** B01, B02.
- **Работа/выход:** `START.md`, отдельные короткие пути для Claude Code/Codex в README, входные адаптеры `CLAUDE.md`/`AGENTS.md`, общие продуктовые инструкции и этапы; постановка задачи, действия/статусы, точки существенного выбора, команды естественным языком остановить/исправить/продолжить. Постоянные инструкции и методики разделены; поведение одинаково по обязательным возможностям.
- **Приёмка:** важный пробел уточняется перед зависимым действием; второстепенные допущения видны. Агент сам выбирает разрешённый следующий инструмент и проверяет результат. Нет обязательного ручного переноса ответа между промптами. Правила разработки не блокируют продуктовый сценарий.
- **Проверка:** неоднозначный запрос, полный бриф без лишнего опроса, изменение цели, остановка, отказ от предложенного варианта; вредоносная команда из источника не становится правилом.
- **Исключено:** новый чат-интерфейс/веб-приложение, разрешение на реальные кампании или внешние сообщения.

## B12. Принять обязательное ядро

- **Цель:** подтвердить обязательные возможности на законченной версии.
- **Вход:** B11, B18, два кейса B03, учёт B13, обязательные команды фактического CI.

Зачёт по шагам: прогон на более раннем коммите засчитывается за шаги, инструкции которых не менялись до финального коммита. В отчёте для каждого такого прогона — разница файлов с финальным коммитом и затронутые ею шаги. Правка, меняющая поведение шагов 1–10, требует повторить весь набор `hard` этой среды и кейса. Сложить один набор из удачных кусков разных прогонов по-прежнему нельзя. Отказ сверх лимита брифа проверяется репликой `s7c` набора `entry` в обеих средах. Заново живьём смотрим правки D17, D18 и D20: модель в журнале, период и база рядом с числом, блок статуса в первой реплике нового чата, находка только из сохранённого текста.
- **Исключено:** заявление о финальной сдаче до B17; автоматическое включение улучшений.
- **Риск/разблокировка:** существенное расширение/исправление после отчёта требует повторения затронутой приёмки и обновления доказательств.
- **Результат приёмки:** `done`, принята командой на версии PR №21 (PR №21), [отчёт](../acceptance/b12-report.md). Пройдены `hard` на обоих кейсах, `entry` и перенос в обе стороны в Claude Code и Codex; шаги 11–12 — набором `faults`.
