- **Минимальный объём:** запись «основание → решение → действие/ответственный → метрика → условие пересмотра»; пользователь добавляет новый материал вручную, агент находит затронутые выводы и предлагает согласованные изменения продукта/коммуникации. История решения сохраняется.
- **Исключено:** обязательный фоновый мониторинг, внешние уведомления и создание поручений в чужих системах.
- **Приёмка:** противоречащая новая таблица меняет действительно зависимые выводы; незатронутые не переписываются произвольно; отозванное основание не считается актуальным фактом. Выбор пересмотра делает человек.
- **Проверка пользы:** те же материалы и новый источник после перерыва для агента и обычного чата, которому разрешено своё резюме; сравнить пропущенные последствия, необоснованные изменения, время и помощь человека. Нет устойчивой пользы — упростить механизм.
- **Стоимость/риск:** оценить после проектирования минимальных связей; стоимость поддержки связей не должна превышать пользу. Это не выбранная заранее главная концепция.

## E02. Роли и маршрутизация

- **Польза:** конкретный класс задачи выполняется качественнее/дешевле либо независимая проверка находит дополнительные содержательные ошибки.
- **Минимальный объём:** один обоснованный маршрут или одна специализированная роль, общий контракт входа/выхода, бюджет и исправление неверного выбора. Можно использовать возможности основной среды; внешний API необязателен.
- **Приёмка:** роль реально вызывается, результат проверяется, ошибочный маршрут исправляется; полный расход включает координацию и повторы. Нет передачи лишних материалов/секретов.
- **Проверка пользы:** одинаковые задания с компонентом и без него; оценить результат, время, стоимость и помощь человека. Само число моделей/агентов не доказательство.
- **Стоимость/риск:** облачный вариант допускается только при устойчивом доступе после временных сторонних сервисов и согласованной платности; автоматическая замена провайдера без проверки качества не обещается.
- **Статус:** `done` с ограничением. В Claude Code роль вызвана: по две проверки после решений, 5–7 замечаний, все приняты. Прогона без проверяющего в Claude Code нет, поэтому польза не доказана. В Codex польза не показана: с ролью и без неё (`-NoReviewer`) кейс доходит до `done` за то же время, проверяющий дал 0–1 замечание. Вызов субагента в журнале Codex не виден ([итог](../acceptance/b12-report.md#итоговый-полный-прогон-на-8bebdc7)): позже выяснено, что `codex exec --json` это событие не пишет, а канарейка показала, что субагент запускается отдельно; отчёт прогона теперь видит его по файлам сессий (D46) ([правки](../acceptance/b12-report.md#правки-после-8bebdc7)). Включён решением команды 12 ноября 2026 года. Сделана одна роль — независимый проверяющий готовых стратегий, плана проверки и обязательств, в отдельном контексте и без доступа к ходу работы агента ([спецификация](../specs/2026-11-12-e02-reviewer.md)). Дополнено 16 ноября 2026 года: команда включила маршрутизацию по модели для модельного собеседника как исключение из заморозки ([спецификация](../specs/2026-11-16-e02-model-routing.md)). - **Проверка:** контрольное интервью и синтетическая беседа; сверка выводов и цитат, согласия/обезличивания при реальных данных.
- **Стоимость/риск:** ограничить число бесед/ролей заранее; не инициировать интервью и не отправлять сообщения без отдельного разрешения.

По одному прогону на ячейку. Включён решением команды 12 ноября 2026 года. Записаны [протокол и сценарий реплик](../acceptance/e06-protocol.md): реплики набора `hard` дословно для агента и обычного чата, по одному прогону на ячейку среда × кейс, прогоны агента берутся из итогового полного прогона, качество оценивают два судьи-модели (Claude Code и Codex) по обезличенным досье, вариант «агент без роли E02» заложен как необязательный. Режим обычного чата и длительность реплик (PR №34), сборщик досье (PR №35) сделаны. E02 принят: вариант без роли запускается ключом `-NoReviewer`.
- **Срок:** отложено решением команды 10 ноября 2026 года до фиксации набора улучшений: каждое включённое улучшение меняет время и расход агента, и прогоны сравнения пришлось бы повторять.
- **Польза:** показать измеримый эффект и цену сложности вместо неподтверждённого обещания.
- **Минимальный объём:** те же две задачи, материалы и критерии для обычного чата и агента; по возможности одинаковые модель, доступы и бюджет. Обычному чату разрешены инструменты и собственное резюме; исключаются только специальные инструкции/память нашего продукта.
- **Приёмка:** до прогонов зафиксированы критерии существенных ошибок/пропусков, вмешательства человека, время и расходы; различия среды и помощи раскрыты. Приёмщик по возможности не знает вариант исполнения при оценке текстов. Отсутствие выигрыша сохраняется в отчёте честно.
- **Проверка:** парные прогоны, исходные результаты и таблица; порядок по возможности чередуется; отдельно восстановление после перерыва. Малый набор не позволяет заявлять статистическую значимость и универсальную экономию.
- **Стоимость/риск:** согласовать число повторов по лимитам; не проводить дорогие бесконечные повторы ради положительного результата. Измерения времени/расходов обязательного ядра уже существуют и переиспользуются при сопоставимых условиях.

## E07. Продвинутый анализ данных

- **Польза:** применить нужный для конкретного вопроса количественный/качественный метод сверх базовых расчётов.
- **Минимальный объём:** один выбранный метод, необходимые данные/предпосылки, воспроизводимая реализация и интерпретация ограничений. Не включать большой набор «на всякий случай».
- **Приёмка:** проверены единицы, период, пропуски и применимость метода; причинность/значимость не заявлены без оснований; вывод можно повторить.
- **Проверка:** контрольный набор с известным результатом, случай нарушения предпосылок, независимое чтение интерпретации.
- **Стоимость/риск:** дополнительные библиотеки/методы фиксируются и оправдываются задачей; неверный метод опаснее отсутствующего.

## E08. Поиск и связанные знания

- **Польза:** находить нужные основания в объёме, на котором навигация по ID и тексту перестаёт быть удобной.
- **Минимальный объём:** сначала измерить пропуски простого поиска; затем добавить один способ улучшения и жизненный цикл индекса при изменении/отзыве источника.
- **Приёмка:** поиск выдаёт исходные основания с локаторами; устаревшее/отозванное не возвращается как актуальный факт; индекс можно восстановить из папки.
- **Проверка:** заранее заданные запросы/ожидаемые материалы, новая версия источника и отзыв; сравнение с базовым поиском.
- **Стоимость/риск:** embeddings/БД не обязательны до подтверждения необходимости; временный облачный индекс не должен лишать переносимую папку работоспособности.

## E09. Дополнительная устойчивость и хуки

- **Польза:** автоматизировать конкретные повторяющиеся проверки/восстановление, уменьшая ошибки и ручную помощь.
- **Минимальный объём:** один полезный event/hook или расширенный сценарий сбоя, явный контракт и состояние повторов. Базовый checkpoint и видимая ошибка уже обязательны в B06/B11.
- **Приёмка:** событие действительно обрабатывается, нет незаметного повторного действия и утечки данных; отсутствие хука в другой среде обозначено.
- **Проверка:** намеренное прерывание/повтор события, восстановление и сравнение с базовым маршрутом; лог действий согласован с результатом.
- **Стоимость/риск:** не добавлять собственный автономный оркестратор и постоянный сервис вместо папки агента; сложность оправдывается найденным сбоем.

## E10. Сканы и распознавание текста

- **Польза:** PDF-скан и фотография документа становятся читаемым материалом, а не только найденным пробелом.
- **Минимальный объём:** один маршрут распознавания, общий с E04: страница передаётся модели среды или локальному распознавателю, текст сохраняется как источник с пометкой «распознано» и номером страницы.
- **Приёмка:** распознанный текст не выдаётся за дословный; число из распознанного фрагмента подтверждается только с этой оговоркой; нечитаемая часть названа.
- **Проверка:** собственный сгенерированный скан с известным текстом, повреждённая страница и сверка чисел.
- **Стоимость/риск:** локальный распознаватель добавляет зависимость и вес установки, распознавание моделью расходует токены; ошибка в цифре опаснее честного отказа.

## E11. Дополнительные форматы материалов

- **Польза:** материалы, которые руководитель реально присылает, читаются без ручной конвертации.
- **Минимальный объём:** один формат по реальной потребности, например PPTX: текст слайдов и заметок с локатором «слайд N».
- **Приёмка:** локаторы работают в `find` и `trace`, пределы входа заданы, неподдерживаемое содержимое (картинки на слайде) названо.
- **Проверка:** сгенерированный файл с маркерами, как для текущих парсеров, и проверка пределов.
- **Стоимость/риск:** каждый формат — новая зависимость и новый парсер; не добавлять форматы «на всякий случай».

## E12. Сайты со входом и на скриптах

- **Польза:** страницы, которые сейчас не читаются утилитой, попадают в источники с текстом.
- **Минимальный объём:** для страниц на скриптах — чтение через браузерный инструмент среды, если он есть, с той же записью источника. Для страниц со входом — инструкция человеку сохранить страницу и записать это как помощь вида `workaround`.
- **Исключено:** ввод паролей агентом, обход защиты от роботов, хранение учётных данных.
- **Приёмка:** сохранённый человеком текст не выдаётся за прочитанный агентом; неполное чтение отмечено `partial`.
- **Проверка:** собственная страница на скриптах и сохранённая копия.
- **Стоимость/риск:** встроенный браузер в утилите тяжёл и ломается при обновлениях; предпочтительно использовать инструмент среды.

## E13. Знания между кейсами

- **Польза:** методические находки и проверенные внешние источники одного кейса доступны в следующем.
- **Минимальный объём:** общий реестр внешних источников и проверенных фактов о рынке с датой и происхождением; выводы и рекомендации прежних кейсов в него не попадают.
- **Приёмка:** прежний ответ агента не становится фактом; устаревшая запись отзывается; кейс по-прежнему переносится одной папкой.
- **Проверка:** второй кейс с пересекающимся источником, отзыв записи и перенос папки без общего реестра.
- **Стоимость/риск:** общий реестр ломает принцип «вся память в папке кейса»; без устойчивой пользы на нескольких кейсах не включать.

## E15. Работа двух чатов над одним кейсом

- **Польза:** два участника или два окна работают с одним кейсом без потери записей.
- **Минимальный объём:** блокировка кейса на время записи с явным владельцем и сроком, понятный отказ второму чату.
- **Приёмка:** нет потерянных и перепутанных номеров записей; зависшая блокировка снимается без ручной правки файлов.
- **Проверка:** два параллельных процесса записи и обрыв одного из них.
- **Стоимость/риск:** блокировки в общей папке ненадёжны на синхронизируемых дисках; сейчас достаточно отказа `number_taken`.

## E16. Форма запроса

- **Польза:** первый запрос сразу содержит поля брифа, агент реже переспрашивает.

Обязательны продукт и свободный запрос; решение и получатель, срок, бюджет и ограничения, материалы, лимиты исследования — необязательны. Страница собирает текст для вставки в чат; файлы кладутся в условленную папку, форма подставляет их имена.

- **Проверка:** запрос из формы и тот же запрос обычными словами, сравнение числа уточнений и времени до утверждения брифа.
- **Стоимость/риск:** условия просят папку, а не программу; форма остаётся необязательной.

Вид — статическая страница или файл, который агент собирает из `outputs/commitments.md`: таблица «человек × действия» или линия сроков.
- **Открытые вопросы:** где и в каком виде хранить команду; когда её вносят (при постановке или перед обязательствами); какой вид нагляднее (доска, линия сроков, таблица загрузки); как отмечать ход работ без внешних систем; откуда вид берёт данные и как остаётся в согласии с документом обязательств.
- **Исключено:** сервер, вход по учётным записям, синхронизация с трекерами задач, уведомления, хранение персональных данных сверх имён и ролей со слов пользователя.
- **Приёмка (черновик):** вид собирается из папки кейса без сети и совпадает с согласованными обязательствами; без команды и без вида обычный путь работает как раньше.
- **Стоимость/риск:** растёт объём вне требуемой папки агента. Нужно решить, даёт ли это баллы по критериям, или это только удобство. Реальные имена в демонстрационном кейсе не нужны.
