## Claude Code

Запуск выполнялся в сессии вкладки Code приложения Claude Desktop на чистой копии `tools/`, `tests/fixtures/`, `pyproject.toml`, `uv.lock` со свежим `.venv`. Подключаемые плагины и MCP для этих шагов не использовались. Прогонов два: основная сессия на Claude Opus 5.5 и отдельный агент с псевдонимом модели `sonnet` и свежим контекстом, который выполнил все шаги [`tools/probe_prompt.md`](../tools/probe_prompt.md). Режим — автоматический во вкладке Code. Доступ — подписка разработчика, вошедшего в Desktop; тариф не записан. Расход на прогон среда не показала, он неизвестен и не равен нулю. Агент чтения страниц занял около 15 секунд, агент полной проверки — около 24 секунд.

| Вход | Инструмент | Результат |
|---|---|---|
| DOCX, PDF, XLSX, CSV | `tools/probe_read.py` через Bash | Все маркеры и локаторы получены, `Выручка!C3` отмечена как формула без значения |
| `rfc-editor.org/rfc/rfc9110.html` | WebFetch | HTTP 200, название «RFC 9110: HTTP Semantics», раздел GET — 9.3.1 |
| Поиск спецификации HTTP Semantics | WebSearch | Найдены `datatracker.ietf.org/doc/html/rfc9110` и `rfc-editor.org/rfc/rfc9110.html` |
| `rfc-editor.org/rfc/rfc0000000.html` | WebFetch | HTTP 404 виден как ошибка, содержимое не выдумано |
| Несуществующий файл | `tools/probe_read.py` | Код 2, статус `unreadable` |
| Бюджет в одно чтение страницы | WebFetch | Прочитана только `example.com`, заголовок получен; `example.org` не открыта и названа непроверенной |

Ограничения:

- WebFetch возвращает только начало большой страницы: в двух прогонах около 39 000 и 100 000 из 564 890 символов. Раздел GET найден по оглавлению, тело раздела в полученную часть не попало. Такое чтение считается частичным.
- WebSearch в этой версии обозначен как работающий только в США, но с этой машины запрос прошёл. Предложение на случай недоступности: агент сообщает об этом и просит у пользователя адреса, чтение WebFetch остаётся. Проверить у второго участника до B09.
- Отдельная CLI из папки Desktop не авторизована, поэтому запуск `claude -p` завершился ошибкой `Not logged in` без расхода. Безголовый прогон требует отдельного входа через `claude auth login`.
- Инициализация CLI 2.1.309 показала `WebSearch`, но не показала `WebFetch` в списке основных инструментов. Маршрут WebFetch подтверждён только для сессии Desktop. Набор инструментов терминальной CLI надо проверить после её входа.

## Codex

На первой машине CLI не находилась в `PATH`; на машине живого прогона доступна командой `codex`. Путь меняется при обновлении, поэтому сначала проверяется `Get-Command`, затем каталог приложения:

```powershell
$codex = (Get-Command codex -ErrorAction SilentlyContinue).Source
if (-not $codex) {
    $codex = (Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\bin\*\codex.exe" |
        Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
}
if (-not $codex) { throw 'Codex CLI not found' }
& $codex --version
```

Первоначальные проверки на первой машине без модели через `codex sandbox` (CLI 0.164.0-alpha.11.1, приложение 26.1027.6604):

| Проверка | Результат |
|---|---|
| `.venv/Scripts/python.exe tools/probe_read.py …pdf` | Работает, маркер ПДФ-2M8 получен |
| То же с CSV и профилем `:read-only` | Работает, маркер ЦСВ-5T2 получен |
| `uv run …` | Отказ: `CreateProcessAsUserW failed: 2`, песочница не находит `uv` |
| `curl.exe https://www.rfc-editor.org/…` | Отказ TLS `SEC_E_NO_CREDENTIALS`, код 35 |

Маршрут использует Python из заранее подготовленного `.venv`, сайты читает встроенным инструментом Codex. Наличие `uv` и сети в командах внутри среды не предполагается.

`codex doctor` на первой машине сообщил об отсутствии авторизации, доступности WebSocket и нехватке места на диске C (2,4 ГиБ при рекомендуемых 5). Это история проверки той машины, а не текущий блокер команды.

### Живой прогон 5 ноября

Передача с первой машины выполнена на другой машине через существующий вход ChatGPT. Из ревизии коммит 4 ветки PR №2 скопированы только `tools/`, `tests/fixtures/`, `pyproject.toml`, `uv.lock` и `.python-version`; создано новое `.venv` командой `uv sync --locked`. Проверены Python 3.12.10, uv 0.12.15, PowerShell 7.6.5. Хеши фикстур совпадают с исходной ревизией. Личная конфигурация отключена через `--ignore-user-config`; использованы только встроенные команды и `web.run`, подключения плагинов не потребовались.

Команда явно запросила `gpt-6.1-sol`, reasoning `low`, поиск `live`; отдельный идентификатор фактически обслужившей модели CLI не вернула. Все пять шагов неизменённого `tools/probe_prompt.md` выполнены в одном принятом прогоне за 48,7 с. Машиночитаемая [запись проверки](evidence/2026-11-05-b02-codex.json) содержит результаты, вывод четырёх парсеров, хеши и счётчики каждой попытки.

Ограничение записи: CLI сохранила действия поиска и поиска по странице, а чтения страниц — как краткие результаты RFC, `Internal Error` без URL/статуса и `Example Domain`. Отдельных событий каждого `open` нет. Точный URL ошибки и утверждение, что `example.org` не открывалась, взяты из финального JSON модели; наблюдения веб-инструмента им соответствуют, но полного независимого журнала чтений нет.

| Шаг | Фактический результат Codex |
|---|---|
| DOCX | `[P2] ДОК-7Q3`, `[T1R2] ДОКТАБ-4K9` |
| PDF | `[p.2] ПДФ-2M8` |
| XLSX | `[Заметки!A1] ТАБ-9X1`, `Выручка!B3 = 1284`, `Выручка!C3` без сохранённого значения формулы |
| CSV | `[R4] ЦСВ-5T2`, одна пустая ячейка; cp1251 — предположение парсера |
| Страница и поиск | «RFC 9110: HTTP Semantics», GET — 9.3.1; одним запросом найден `https://www.rfc-editor.org/rfc/rfc9110.html` |
| Недоступная страница | Для `rfc0000000.html` инструмент вернул `Internal Error`; статус 404 не подтверждён, содержимое не выдумано |
| Бюджет одного чтения | `example.com` — «Example Domain»; `example.org` не открывалась, бюджет назван исчерпанным |

Режим принятого прогона — `--approve-for-me`: автоматическое рассмотрение запросов при ограничении записи рабочей папкой. Вмешательства человека внутри прогона не было. Две предыдущие полные попытки с `-s read-only` (28,7 с) и `-s workspace-write` (30,5 с) получили `blocked by policy` до запуска всех четырёх парсеров. Они не приняты; их успехи веб-шагов не объединялись с последним результатом. Одна смена режима записи не помогла, документированный режим рассмотрения команд подтвердил рабочий маршрут. Защита, правила выполнения и hooks не отключались. [Справка OpenAI](https://learn.chatgpt.com/docs/cli/reference) описывает `--approve-for-me`, `--ignore-user-config` и `-c`; проверена 5 ноября 2026 года.

CLI сообщила для принятого прогона 110 838 входных токенов, из них 87 808 кешированных, и 738 выходных. Для двух неудачных попыток: 74 965 / 57 984 / 669 и 83 076 / 61 952 / 688 соответственно (вход / кеш / выход). Это счётчики `turn.completed`, не размер контекста, не расход квоты Plus и не полный учёт автоматического рассмотрения. Денежная стоимость и время до первого полезного результата неизвестны; подписочный запуск не записан как бесплатный API.

## Чтение сайта через утилиту (B04)

Проверка 5 ноября 2026 года: страница читается инструментом среды, текст сохраняет `tools/read_material.py add-web`, затем `find` и валидатор. Вход одинаковый: RFC 9110 и несуществующая `rfc0000000.html`. Полный сценарий продукта это не заменяет.

| | Claude Code | Codex |
|---|---|---|
| Версия и проверяющий | Desktop, инструмент WebFetch, участник 1 | CLI `0.166.0-alpha.5.1`, `web.run`, участник 2 |
| RFC 9110 | HTTP 200, дословно 39 415 из 564 890 символов, запись `partial` | Сохранено первое предложение Abstract из 7447 строк, запись `partial` |
| Недоступная страница | HTTP 404, запись `unavailable`, код 2 | `Internal Error`, HTTP-статус не показан, запись `unavailable`, код 2 |
| `find` | Локатор `paragraph`, индекс 3 | Локатор `paragraph`, индекс 2 |
| Валидатор | Ошибок и предупреждений нет | Ошибок и предупреждений нет |

Claude Code проверен дважды с одинаковым результатом: на коммите 4 ветки PR №5 до исправлений ревью и на коммите 6 ветки PR №5 после них, WebFetch вызывал отдельный агент. Модель Codex и версия приложения в отчёт не попали, SHA проверенной ревизии тоже: проверка выполнялась на ветке PR №5.

Что выяснилось:

- WebFetch смешивает дословное начало страницы со сводкой модели, а сводка противоречила тексту: называла Abstract недоступным. Процедура разрешает сохранять только дословную часть.
- В Codex первая попытка упала: папка кейса в системном временном каталоге была видна PowerShell, но недоступна Python. `add-web` вернул код 5, `find` — код 4, ложных записей не появилось. Повтор в рабочей папке Codex прошёл. Кейс нужно держать в `projects/` внутри репозитория.
- `codex --version` вывел предупреждения об отказе доступа к временным каталогам и псевдонимам `PATH`, но версию вернул.

Изоляция подтверждена журналами, а не только флагами:

- Claude Code 2.1.317, `claude-sonnet-5-5`: `claude -p --setting-sources project --disable-slash-commands --strict-mcp-config --no-session-persistence`. Событие запуска показало пустые списки навыков и серверов MCP и только встроенные плагины. Клон лежал вне домашней папки: из временной папки подтягивался личный `~/.claude/CLAUDE.md`.
- Codex 0.166.0-alpha.6, запрошена `gpt-6.1-sol`: пустой `CODEX_HOME` с отдельным входом и `--ignore-user-config`. В журнале `--json` нет следов плагинов. Один `--ignore-user-config` плагины не отключает: без пустого `CODEX_HOME` в прогоне загрузился личный плагин. Запись о прогоне B02 выше нужно читать с этой оговоркой.

Коды завершения: Codex перечислил их по запускам, в Claude Code правила разрешений не дали напечатать код, успех проверен по ответам JSON. `Режим: продукт.` стоит в первом сообщении обеих сред, в Codex итоговое сообщение эту строку не повторяет.

Предварительные прогоны 5 ноября шли с личной конфигурацией и в приёмку не входят. По ним в процедуру и методику добавлены: запись противоречия при первом `add`, порядок записи вывода, общее суждение без показателя, значение в тексте при конфликте, указание пользователя как объяснение противоречия и пересмотр зависимых выводов. Смысловая проверка основания держится на чтении: утилита проверяет только наличие цитаты в указанном блоке.

## Общий маршрут

Адаптер двух сред: локальные файлы читаются одной утилитой Python, сайты и поиск — встроенными средствами среды.

| Шаг | Claude Code | Codex |
|---|---|---|
| Подготовка, разово, нужна сеть | Как в START: на Windows Python в `.python` проекта | Как в START, до запуска среды. На Windows обязательно: песочница не запускает Python из профиля пользователя (B14) |
| Локальные файлы | `.venv/Scripts/python.exe tools/read_material.py <команда>`, проверка файла — `inspect <файл>` | То же, в песочнице |
| Сайт | WebFetch и WebSearch в Desktop; терминальная CLI не проверена | Встроенные поиск и чтение `web.run`, проверены с `web_search=live` |
| Диагностика | `claude auth status` проверена; `/doctor` не запускалась | `codex --version`, `codex login status`; первоначальная `codex doctor` на первой машине |

Вне Windows вместо `.venv/Scripts/python.exe` используется `.venv/bin/python`.

Сторонние сервисы вместо встроенных не нужны: маршрут использует локальные парсеры и встроенные веб-инструменты каждой среды. В принятом Codex-прогоне пользовательская конфигурация отключена, внешние API и плагины не вызывались. Значения переменных окружения и файлов авторизации не читались и не публиковались.

## Другие среды (B18)

Агент не привязан к двум средам: журнал принимает любое короткое имя среды, процедуры описывают поиск и чтение страниц как возможности среды. Уровни поддержки:

| Уровень | Среды | Что подтверждено |
|---|---|---|
| Принято | Claude Code, Codex | Полный сценарий, новый чат и перенос папки в обе стороны (B09, B12, B14) |
| Совместимо | Cursor, Windsurf, GitHub Copilot, OpenCode и другие | Ничего живьём; путь должен работать, если среда выполняет условия ниже |

Условия совместимости:

- Среда читает `AGENTS.md` в корне папки. Claude Code вместо него читает `CLAUDE.md`, который импортирует `AGENTS.md`.
- Агент может запускать команды в терминале этой папки: утилиты `tools/` нужны на каждом шаге.
- Для сайтов нужен встроенный поиск и чтение страниц либо сеть у команд для `fetch-web`. Без них агент работает с файлами пользователя и говорит об этом при постановке.

Чем совместимая среда отличается от принятых:

- Лимит поиска брифа держится на записи действия: хук `tools/web_guard.py` есть только в Claude Code. `action start` и `fetch-web` отказывают сверх лимита в любой среде.
- Расход и версия среды записываются, только если среда их показывает; иначе остаются неизвестными.
- Подсказки разрешений, песочница и сеть у команд не проверялись: первый запуск может потребовать разрешить команды из этой папки.

Живая проверка в Cursor на версии B18: не запускалась.

- Песочница Codex на Windows (B14, CLI 0.167.0-alpha.3.2): команды идут от ограниченного пользователя, которому закрыт профиль владельца. Python из `%LOCALAPPDATA%\Programs\Python` не запускается: `CreateProcessAsUserW failed: 5`, а `.venv` на нём отвечает `No Python at …`. Пакеты, поставленные `uv` жёсткими ссылками на кеш в профиле, сохраняют права кеша: импорт падает с `Permission denied`. Поэтому на Windows Python ставится в `.python` внутри проекта (`UV_PYTHON_INSTALL_DIR` и `--managed-python`), а `pyproject.toml` задаёт `link-mode = "copy"`. Задать папку Python в `pyproject.toml` или `uv.toml` `uv` 0.12.15 не позволяет. Проверено `codex sandbox` без модели. В полных прогонах этого не видно: `--approve-for-me` одобряет выход из песочницы.

## Пределы входов

Значения — в [`tools/input_limits.json`](../tools/input_limits.json). Превышение возвращает код 3 и `over_limit` без частичного результата. Предел вывода ограничивает один показ, а не сохранённое извлечение: `show` продолжает с места по полю `next`.

| Предел | Значение |
|---|---|
| Размер файла | 25 МиБ |
| Страницы PDF | 300 |
| Текст MD, TXT, DOCX | 1 000 000 символов |
| Строки таблицы | 100 000 на лист |
| Столбцы таблицы | 200 |
| Ячейки таблицы | 2 000 000 на файл |
| Вывод одного вызова | 20 000 символов |

Замер на границах (`tools/measure_limits.py`, чистое время процесса):

| Файл | Размер, МиБ | Время, с | Результат |
|---|---|---|---|
| CSV, 100 000 строк × 10 | 18,2 | 0,5 | `partial`, код 0 |
| CSV, 100 001 строка | 18,2 | 0,4 | `over_limit`, код 3 |
| XLSX, 100 000 строк × 20 | 6,3 | 63,2 | `partial`, код 0 |
| PDF, 300 страниц | 0,2 | 1,7 | `partial`, код 0 |
| DOCX, около 1 млн символов | 0,04 | 0,6 | `partial`, код 0 |

Предел по ячейкам введён после ревью: XLSX на 7 млн ячеек читался 230 секунд, дольше стандартных 120 секунд команды Bash в Claude Code. На границе нового предела чтение занимает 63 секунды на этой машине, другим машинам может понадобиться больший тайм-аут.

Пустой файл даёт код 2 и `empty`, PDF со страницами без текста — `partial`. Для CSV кодировка cp1251 определяется по исключению, поэтому отчёт ставит `encoding_assumed: true`, а статус становится `partial`; KOI8-R так не отличить, и файл нужно проверить глазами. Флаг `delimiter_assumed: true` просит уточнить разделитель. Подробности чтения — в [спецификации B04](specs/2026-11-05-b04-read-materials.md).

Замеры выше и пробы B02 выполнены до B04 утилитой `tools/probe_read.py`, её можно запустить на ревизии PR №2. Сейчас `tools/measure_limits.py` и `tools/probe_prompt.md` используют `tools/read_material.py`.

Для B04 остаётся:

- чтение по диапазону или странице: предел вывода показывает только начало большого файла, такой источник не считается прочитанным целиком;
- DOCX: вложенные таблицы и элементы управления содержимым сейчас теряются, объединённые ячейки дублируются, отчёт об этом не сообщает;
- большая первая страница PDF не попадает в вывод, скрытые листы XLSX не помечены.

## Изображения (E04)

10 ноября 2026 года, ветка `feature/e04-screenshots`, [спецификация](specs/2026-11-10-e04-screenshots.md). Скриншоты PNG, JPEG, WebP регистрируются как источники `image`, наблюдения пишет агент ([процедура](../agent/workflows/read-images.md)); публичные страницы снимает необязательная команда `capture-web`.

**Просмотр изображения моделью.**

| Среда | Инструмент | Статус |
|---|---|---|
| Claude Code | встроенное чтение файла (`Read`) открывает изображение | Проверено на 2.1.325, 15 ноября 2026 года ([финальные проверки](acceptance/final-checks-report.md#e04-скриншоты)) |
| Codex | встроенный `view_image` | Проверено на `codex-cli 0.167.0-alpha.3.2` с флагами скрипта прогона, 15 ноября 2026 года. Вызовы видны только в файле сессии `CODEX_HOME/sessions`, в журнал `exec --json` они не попадают |

Поведение агента на скриншотах проверено в обеих средах. Хуки проекта (`.claude/settings.json`) касаются только `WebSearch` и `WebFetch`, чтение файлов `sources/*.png|jpg|webp` они не затрагивают; для Codex в репозитории хука нет.

**Пределы.** Размер файла — общий `max_file_bytes` (25 МиБ). Сторона изображения не больше `max_image_side` = 8000 пикселей: основание — наибольшая сторона, которую принимает API Claude для изображений; большее изображение дало бы код 3 и просьбу прислать фрагменты. Высота больше ширины в 2,5 раза получает в `limits` пометку, что детали могут потеряться. Число частей снимка `max_capture_parts` = 4, ожидание загрузки `capture_timeout_seconds` = 30.

**Локальный прогон `capture-web`.** Windows 11, Python 3.12.15, uv 0.13.5, Playwright 1.65.0 (группа `screenshots`), Chromium из сборки Playwright (`chromium-1254`).

- `uv sync --locked --group screenshots`, затем `.venv/Scripts/python.exe -m playwright install chromium`; каталог `ms-playwright` на диске вырос до 741 МБ (Chromium, headless shell, ffmpeg).
- `uv run --locked --group screenshots python -m unittest tests.test_web_capture -v`: 30 тестов, все прошли, десять тестов с реальным браузером выполнились, а не пропущены. Страница 3000 px на окне 1366×768 даёт 4 части, 404 — `http_error`, адрес 127.0.0.1 без разрешения — `address_blocked`, `--mobile` и предел частей соблюдены. Проверены на локальном сервере: переадресация `/redir` → `/secret` при предикате, блокирующем `/secret`, даёт `address_blocked`; запрос страницы к заблокированному адресу прерывается, а страница снимается; всплывающее окно не загружается; сокет не соединяется; видимые `iframe` и `object` не делают страницу пустой; страница, зависающая в бесконечном цикле, останавливается сторожем с кодом `timeout`.
- Затем `uv sync --locked` вернул обычное окружение: Playwright не установлен, тест реального снимка в обычном запуске пропускается.
- После добавления прокси (12 ноября 2026 года, Windows 11, Python 3.12.10, Playwright 1.65.0, `chromium-1254`): 38 тестов, все прошли, двенадцать с реальным браузером выполнились. Шесть тестов прокси без браузера идут и в CI. Контрольная проверка: если запустить браузер без прокси, три новых теста с браузером падают (имя, известное только правилу; переадресация на внутреннее имя; адрес 127.0.0.1 мимо прокси).

**Защита `capture-web`.** Адрес проверяется до запуска браузера. Затем браузер ходит в сеть только через локальный прокси `tools/capture_proxy.py` и сам имена не разрешает: на каждое соединение, в том числе на каждый шаг переадресации, прокси один раз разрешает имя правилом `fetch-web` и соединяется ровно с этим адресом. Отказанное имя не получает соединения, запрос никуда не уходит. Поэтому закрыты оба прежних предела: переадресация на внутренний адрес и подмена DNS (DNS rebinding) между проверкой и загрузкой. HTTPS идёт через прокси туннелем: прокси не видит страницу и сертификат, сертификат проверяет браузер. Адреса 127.0.0.1 и localhost тоже идут через прокси: Playwright сам добавляет `<-loopback>` в список обхода. WebRTC запрещён UDP мимо прокси (`--force-webrtc-ip-handling-policy=disable_non_proxied_udp`). Вторым рубежом остаются прежние проверки: маршрут на уровне контекста пропускает запросы только к публичным адресам и прерывает запросы всплывающих окон (окно закрывается сразу), `route_web_socket` закрывает сокеты страницы, не соединяя их с сервером, после загрузки проверяются все шаги цепочки переадресаций и итоговый адрес. Весь снимок от запуска браузера до последнего скриншота ограничен `capture_timeout_seconds` плюс 5 секунд запаса: по истечении сторож принудительно останавливает драйвер Playwright и браузер (через закрытые атрибуты драйвера закреплённой версии; без них остаются таймауты отдельных вызовов), ответ — `timeout`. Сокеты, которые открывает Web Worker, тоже идут через прокси, отдельным тестом это не проверялось.

Обычный `uv sync --locked` удаляет группу `screenshots` из `.venv`: после него снимки снова недоступны, пока не выполнены обе команды установки. Основной путь, CI и чистый запуск Playwright не ставят.

**Не проверено.** Снимок реального публичного сайта в обеих средах и отказ без Playwright. Честность наблюдений, метки экрана и разделение факта и гипотезы проверены вживую 15 ноября 2026 года ([финальные проверки](acceptance/final-checks-report.md#e04-скриншоты)).

## Воспроизведение

Из корня репозитория:

```powershell
uv sync --locked
.venv/Scripts/python.exe -m unittest discover -s tests
uv run --group fixtures python tools/measure_limits.py
```

Фикстуры закоммичены. `uv run --group fixtures python tools/make_probe_fixtures.py` нужен только при их изменении: байты DOCX и XLSX при каждой генерации отличаются.

Живая проверка Codex из чистой копии входов с подготовленным `.venv`, после поиска `$codex` как выше. Эта команда с `web_search=live` проверена целиком:

```powershell
$OutputEncoding = [Text.UTF8Encoding]::new($false)
$env:PYTHONIOENCODING = 'utf-8'
$env:PYTHONUTF8 = '1'
Get-Content -Raw -Encoding utf8 tools/probe_prompt.md | & $codex exec --ignore-user-config --ephemeral --skip-git-repo-check --approve-for-me -m gpt-6.1-sol -c model_reasoning_effort=low -c web_search=live --json -
```

Для офлайн-тестов в ограниченной Windows-среде может понадобиться временный каталог внутри рабочей папки. Первая локальная попытка получила `WinError 5` в системном sandbox Temp; после задания `TMP` и `TEMP` на локальную папку прошли 20/20 тестов. Это настройка одного процесса, глобальная конфигурация не меняется:

```powershell
New-Item -ItemType Directory -Path .work/test-temp -Force | Out-Null
$env:TMP = (Resolve-Path -LiteralPath .work/test-temp).Path
$env:TEMP = $env:TMP
.venv/Scripts/python.exe -m unittest discover -s tests
```

## Остаточные ограничения и приёмка

1. Переданная проверка Codex выполнена; отсутствие входа на первой машине не блокировало приёмку B02. B01 принята, поэтому B04/B06/B07/B13 доступны.
